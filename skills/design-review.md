# 设计评审清单

按顺序过一遍，每一条都要指向具体位置和具体后果。

## 1. 问题定义
- 方案要解决的用户任务，能一句话说清吗？
- 有没有反例：什么情况下这个问题会消失？

## 2. 证据
- 每条关键结论背后是什么证据？用户访谈、埋点、竞品还是假设？
- 没有证据的结论，写进"待验证"而不是正文。

## 3. 流程与状态
- 空、加载、部分成功、失败、无权限，五个状态是否都有出口？
- 用户走错路能不能回来？返回后数据还在吗？

## 4. 信息层级
- 首屏能不能回答"我在哪、我能做什么、下一步是什么"？
- 有没有三个以上的同权重按钮抢注意力？

## 5. 实现风险
- 开发成本、性能、可访问性（键盘、对比度、屏幕阅读器）、国际化。
- 长文本、极端数值、网络不稳定下的表现。

## 6. 结论格式
```
致命问题：…
证据缺口：…
实现风险：…
被忽略的替代方案：…
如果只能改一处：…
```
