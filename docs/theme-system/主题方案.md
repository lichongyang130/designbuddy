# 主题系统方案（对齐 Gamma Themes）

> 一句话：仓库里已经有 **三套"半个主题系统"**，但没有一套能做到 Gamma 那样"换主题不动内容"。
> 这份方案把主题抽成**独立资产**，并打通它必须生效的三个地方：生成前、编辑时、导出时。

---

## 0. 先给结论

| 问题 | 现状 | 本方案 |
|---|---|---|
| 能换主题吗 | 只能"换个框架"，骨架和配色一起换 | 拆开：框架管叙事结构，主题管视觉 |
| 选了主题能看到吗 | 大纲页有色卡，**进入编辑器后主题丢失** | 编辑器实时生效（CSS 变量） |
| 导出的 PPTX 是主题色吗 | **不是**，写死 `17292C / F2F1EB` | 真实注入 `theme1.xml` + 每页配色 |
| 有自己的主题吗 | 180 套设计系统，但只服务代码项目 | 派生 24 套 + 12 套原生演示主题 |
| 能自定义吗 | 不能 | 主题编辑器（颜色/字体/图形/图片/Logo/图表） |
| 能导入品牌吗 | 不能 | 从 PPTX 的 `theme1.xml` 提取（只提取，不臆造） |

工作量：P0 约 4 天、P1 约 6 天，P2 一周起。P0 做完就能"选主题 → 看到 → 导出也是它"。

## 1. 现状盘点（都是可验证的事实）

### 1.1 四套互不相通的配色源

| # | 位置 | 内容 | 问题 |
|---|---|---|---|
| A | `frontend/workspace/pptFrameworks.ts` | 10 套框架，每套内联 `theme`（primary/accent/background/surface/text/muted/字体） | **叙事结构 = 配色**。想换配色就得换框架，骨架也一起变 |
| B | `frontend/workspace/pages/PptPage.tsx` | 演示稿编辑器 | `grep theme PptPage.tsx` → **0 命中**，主题在这里完全丢失 |
| C | `apps/web/src/components/scene-demos/Slides.tsx` `exportPptx()` | PPTX 导出 | 硬编码 `17292C`（封面底）、`F2F1EB`（内页底）、`273E40`（正文墨色） |
| D | `design-systems/catalog.json` | 180 套完整 token（color/typography/spacing/radius/shadow/components/accessibility） | 只被 `applyDesignSystemTokens`（代码项目）与 Studio 的 `designContract` 用，**演示稿完全没用** |
| E | `frontend/workspace/pages/StudioPage.tsx` | 手写 PPTX | `theme1.xml` 里写死 Linear 的 `5E6AD2`，任何主题都一样 |

### 1.2 用户体验上的三条断裂

1. **大纲页选的是"框架"，不是"主题"**：用户以为在选风格，其实在选叙事结构。
   `PptOutlinePicker` 的卡片只展示 `candidate.theme` 四个色块，进 `PptPage` 后这些颜色一个都不生效。
2. **"换个框架 🔀"是唯一的换风格入口**，但它会重排页面内容 —— 已编辑的文字会被冲掉。
3. **导出与预览不一致**：屏幕上看到的和 PPTX 里的不是一套颜色，这在交付场景里是硬伤。

### 1.3 已有的可复用资产（别重复造）

- `design-systems/catalog.json`：180 套，含 `tokens.color / typography / spacing / radius / shadow`，字段完整、可直接映射成主题。
- `createDesignContract()`：已经能把 token 渲染成给模型看的"设计契约"文本，生成时可直接复用。
- `skillPermissions` / `plugin-registry.ts`：服务端持久化的现成范式（sqlite + `sameOrigin` + 事件日志），自定义主题服务端化可以照抄。
- `react-window` 已在依赖里；`plugins.css` 的卡片/筛选样式可作为 `/themes` 的视觉基线。

## 2. Gamma 的主题到底做了什么（对齐清单）

根据 Gamma 官方帮助文档与产品说明，主题能力可拆成 6 件事：

1. **主题 ≠ 模板**：主题控制颜色、字体、Logo、卡片形状/描边/阴影、图片风格；模板是预置内容。
2. **画廊**：按风格浏览，卡片是真实效果预览，不是纯色块。
3. **生成前可选、生成后可换**：换主题时内容不动。
4. **主题编辑器**：Colors / Fonts / Logo / Design / Images / Charts / Custom CSS。
5. **导入品牌**：上传 `.pptx` 或 Google Slides，提取颜色/字体/Logo 生成主题。
6. **作用域**：Gamma 5 里主题**跟着文件走**；也可保存到工作空间共享；导出时嵌入字体。

> 我们的差异：**不嵌入字体文件**（体积与授权问题），只写字体名并在 UI 说明"对方机器没有该字体会回退"。这条要写在界面上，不能假装嵌入。

## 3. 数据模型：`DeckTheme` v1

新增 `shared/deckTheme.ts`（前后端共用类型 + 校验），主题是纯数据，不含任何可执行内容。

```ts
export type DeckTheme = {
  id: string;                       // "theme-01" | "custom-<uuid>" | "imported-<uuid>"
  name: string;                     // 「雾青编辑」
  kind: "preset" | "derived" | "custom" | "imported";
  source?: { systemId?: string; filename?: string };  // derived 时指回 design-system
  tags: string[];                   // ["极简","深色","提案"]
  palette: {
    background: string; surface: string; text: string; muted: string;
    primary: string; accent: string; border: string;
    onPrimary: string; success: string; warning: string; danger: string;
  };
  typography: {
    headingFont: string; bodyFont: string;   // 只允许内置/系统字体白名单
    scale: number[]; lineHeight: number; letterSpacing: number;
    headingWeight: 500 | 600 | 700; headingTransform: "none" | "uppercase";
  };
  shape: { radius: number; stroke: number; shadow: "none" | "soft" | "raised"; padding: number };
  layout: {
    density: "compact" | "default" | "airy";
    cover: "full-bleed" | "split" | "centered" | "minimal";
    eyebrow: "mono" | "caps" | "pill";
    accentBar: boolean; divider: "line" | "space" | "none";
  };
  imagery: {
    style: "photo" | "illustration" | "abstract" | "none";
    overlay: number;          // 0–1，封面图上压暗程度
    keywords: string[];       // 给生成用的风格词
  };
  logo?: { assetId?: string; placement: "cover" | "header" | "footer"; maxHeight: number };
  charts: { palette: string[]; grid: boolean };
  customCss?: string;         // ≤ 4 KB，仅 HTML 导出生效
  meta: { createdAt: string; updatedAt: string };
};
```

### 校验规则（放服务端，前端同源复用）

| 规则 | 处理 |
|---|---|
| 颜色必须是 6 位 hex | 非法 → 400，指出字段 |
| 文本/背景对比度 < 4.5:1 | **不拦截**，返回 `warnings[]`，前端黄条显示具体比值与建议 |
| 字体不在白名单 | 400 + 可选字体列表（避免"设置了却没有"的假象） |
| `customCss` > 4 KB 或含 `@import`/`url(` | 400（禁止外链与远程加载） |
| 单主题序列化 > 32 KB | 400 |
| `charts.palette` < 3 色 | 自动补足到 3，并记 warning |

## 4. 主题库：怎么从 180 套里长出"演示可用"的主题

**不复制一份 JSON**（会立刻发霉），而是加一个派生脚本：

```
design-systems/catalog.json (180, 现有，不动)
        │  scripts/build-theme-catalog.mjs  （幂等，CI 可校验）
        ▼
themes/catalog.json
  ├─ presets:  12 套原生演示主题（手写，脱离 UI 设计系统，专注"演示稿好看"）
  └─ derived:  24 套从 design-system 派生的演示主题（精选，不是 180 全上）
```

派生规则（写成纯函数 `deriveDeckTheme(system) → DeckTheme`，可单测）：

- `background ← tokens.color.background`，`surface ← tokens.color.surface`
- `primary ← tokens.color.primary`，`accent ← tokens.color.success`（沿用 `applyDesignSystemTokens` 的既有约定，避免两套语义）
- `typography.headingFont/bodyFont ← tokens.typography.display/body`，`scale/lineHeight` 直接继承
- `shape.radius ← tokens.radius[1]`，`shadow` 按 `tokens.shadow` 数量映射 `none/soft/raised`
- 演示稿专属字段（`layout` / `imagery` / `charts`）用**风格模板**填充：`极简 → minimal + none`、`编辑感 → centered + photo`、`科技 → full-bleed + abstract`

**为什么只上 24 套派生**：180 套里有 93 套集中在金融科技/内容出版/电商零售，视觉高度同质；全上等于把同 5 个配色刷 36 遍，反而削弱"选主题"的决策价值。筛选规则：按 `primary` 色相去重，每 15° 取一个代表，再人工替换掉明显不适合演示的（如纯白 + 纯黑的管理后台色）。

测试（`themes/derive.test.mjs`）：
- 24 套全部通过 schema 校验
- 任一两套的 `palette.primary` 颜色距离（ΔE）> 8，否则告警重复
- 12 套原生主题的正文/背景对比度 ≥ 4.5

### 5.2 卡片预览必须"真"

复用**真实渲染组件**（`Slides` 的 cover / cards / chart 三种版式）渲染成 16:9 缩略图，而不是画色块。
实现：`<ThemePreview theme layout="cover" />`，内部就是给 `--ppt-*` 变量赋值 + 渲染 mini deck，纯 CSS，无图片、无 canvas、无网络请求。

> 这条是对现有 `PptOutlinePicker` 的修正：那张卡片只显示 4 个色块，用户无法预判"我的内容放进去长什么样"。

### 5.3 详情抽屉

点卡片 → 右侧抽屉（复用 `plugins.css` 的抽屉骨架）：

- 大预览：封面 / 要点 / 图表 三页横排，可点开全屏
- Token 列表：主色、强调色、字体对、圆角、密度
- 可访问性：正文对比度 8.2:1 ✓、强调色对比度 4.6:1 ✓
- 动作：**应用到当前演示稿** / **以此新建** / **设为默认** / 复制主题 / 编辑（派生主题会提示"将另存为自定义"）
- 底部一行：`主题只管外观，不改变你的文字与结构。`

> 设计稿：`docs/theme-system/02-theme-editor.png`

### 5.4 主题编辑器

左栏分组，右栏 16:9 实时预览（可切 3 种版式）：

| 分组 | 控件 |
|---|---|
| 颜色 | 背景 / 表面 / 正文 / 次要 / 主色 / 强调 / 边框 / 图表 5 色；每个支持 hex 输入 + 取色器 |
| 字体 | 标题字体、正文字体（白名单下拉）、字号档位（紧凑/默认/宽松）、行高、字距、标题字重 |
| 图形 | 圆角、描边、阴影（无/轻/浮起）、卡片内边距、分隔（线/留白/无） |
| 图片 | 风格（照片/插画/抽象/无）、封面压暗强度、风格关键词 |
| Logo | 上传（≤ 500 KB，PNG/SVG）、位置、最大高度 |
| 图表 | 5 色序列、是否显示网格 |
| 高级 | 自定义 CSS（仅 HTML 导出），带"不会作用于 PPTX"的说明 |

- 改动即时写 `theme` 草稿（zustand），预览 `< 16ms`
- 底部固定：`取消 / 另存为副本 / 保存`
- 保存前跑校验，warning 以黄条呈现，**不阻断保存**（人可以坚持自己的品牌色）

### 5.5 导入 PPTX

- 客户端用 `fflate` 解压（已有依赖），读 `ppt/theme/theme1.xml`
- 解析 `a:clrScheme`（dk1/lt1/accent1–6）、`a:fontScheme`（major/minor latin）
- 映射成 `DeckTheme` 草稿：`background ← lt1`、`text ← dk1`、`primary ← accent1`、`accent ← accent2`、字体名原样带入（不在白名单则提示将回退）
- 解析失败/不是 pptx → 明确报错，**不生成"看起来像"的假主题**
- 不做：版式拟合、母版重建、Logo 自动抠图

## 6. 三个消费点（不做这三处，主题就是装饰）

### A. 生成前 —— `PptOutlinePicker` 与首页

```
首页输入「PPT制作」→ PptPage/PptOutlinePicker
   顶部：叙事框架（3 选 1）   ← 保持不变
   新增：主题（横向 6 张缩略卡 + 「全部主题 →」）
   候选大纲卡：用【所选主题】渲染，而不是框架内联色
```

- `createPptProject(prompt, framework, themeId)` 增加第三个参数
- 首页记住上次主题（`usePreferences.lastThemeId`），第二次生成不用重选
- 主题选择**不影响**框架推荐；两者正交

### B. 编辑时 —— `PptPage`

- 工具栏加「主题」按钮（在「换个框架 🔀」左侧），打开右侧抽屉，横排主题卡，点一下立即应用
- 实现：给 `.ppt-workspace` 注入 CSS 变量（`--ppt-bg / --ppt-surface / --ppt-ink / --ppt-primary / --ppt-accent / --ppt-border / --ppt-radius`），幻灯片/缩略图/工具栏同步变化
- **「换个框架 🔀」改成只换骨架不动主题** —— 这是 Gamma 的行为，也是现在最容易让用户踩坑的地方
- 抽屉底部：`把当前主题设为默认`

### C. 导出时 —— 让 PPTX 真的是这个主题

`exportPptx(slides, { theme })`：

| 位置 | 改法 |
|---|---|
| 封面底色 | `theme.palette.primary`（深色主题压暗 12%） |
| 内页底色 | `theme.palette.background` |
| 正文墨色 | `theme.palette.text` |
| 强调线/图表 | `theme.palette.accent` / `theme.charts.palette` |
| `ppt/theme/theme1.xml` | 由 `buildPptxThemeXml(theme)` 生成（对齐 `clrScheme`/`fontScheme`），**替换 StudioPage 里写死的 Linear 配色** |
| 字体 | `headFontFace` / `bodyFontFace` ← 主题字体；导出完成提示"若对方机器无此字体，将回退为系统字体" |

验收方式（可自动化）：导出后解压 pptx，断言 `ppt/theme/theme1.xml` 里 `accent1` == 主题 `primary`，且第一页 `背景色` == 主题 `primary` 的 RGB。

### D. 顺带打通（低成本、高一致性）

- `StudioPage` 的 PPTX 导出复用同一 `buildPptxThemeXml`
- 技能产出 `infographic.compose` / `social.carousel` / `brand.system` 读取同一 token（它们本来就是 `design.tokens` 语义）
- HTML / PDF 导出用 `themeToCssVariables(theme)`，保证三种导出同色

## 7. 状态与持久化

```
themeStore (zustand, persist)
 ├─ presets:  DeckTheme[]       只读，来自 themes/catalog.json（懒加载）
 ├─ custom:   DeckTheme[]       可写，localStorage
 ├─ defaultThemeId?: string
 └─ actions: applyToDeck / saveCustom / duplicate / remove / import
```

- **作用域对齐 Gamma 5**：主题存在 `PptProject.themeId`（跟文件走）；`defaultThemeId` 只影响"新建时预选"。
- **向后兼容**：`normalizeProject()` 里 `themeId` 缺省 → `frameworkId` 对应框架的内联 theme 转成临时 `DeckTheme`（迁移函数 `migrateFrameworkTheme()`），旧文件打开颜色不变。
- **跨设备**：P2 加服务端 `/api/themes`（sqlite 表 `themes(owner_id, id, name, json, created_at, updated_at)`，复用 `plugin-registry.ts` 的 `sameOrigin` + 事件日志套路）。
- **可收藏**：`WorkspaceAsset.type` 增加 `"themes"`，`/assets` 与首页「我的插件」旁的资产入口可复用。

## 8. API 契约（P2，自定义主题跨设备）

```http
GET    /api/themes                    → { catalogVersion, custom: DeckTheme[] }
POST   /api/themes                    { name, theme } → { theme }        // 服务端校验后落库
PATCH  /api/themes/:id                { name?, theme? } → { theme }
DELETE /api/themes/:id                → { ok: true }
```

- 全部写接口走 `sameOrigin()`，跨站 403（与 `plugin-registry` 一致）
- 服务端做 §3 的全部校验，**warning 存进 `json.warnings`**，GET 时一并返回
- 单用户上限 50 套，超限返回明确文案
- 不做：团队共享、权限分级、主题市场（P3）

## 9. 权限、诚实性与可访问性

| 项 | 立场 |
|---|---|
| 主题会不会改内容 | 不会。只改视觉 token，`slides[]` 一字不动 |
| 自定义 CSS | 只在 HTML/PDF 导出生效；PPTX 不支持，界面明说；禁止 `url(`/`@import`（防外链与远程加载） |
| 字体 | 只写字体名，不嵌入字体文件。导出提示"对方机器缺字体会回退"，不谎称嵌入 |
| 对比度 | 计算并展示真实比值（WCAG AA 4.5:1）；不足只警告，不偷偷改色 |
| 导入 PPTX | 只解 `theme1.xml`，不执行宏、不解析外链、不请求网络 |
| 深色主题打印 | 导出 PDF 前提示"深色背景在打印时耗墨"，给浅色替身建议 |

## 10. 性能

| 关注点 | 方案 |
|---|---|
| 首页成本 | **0**：主题只在 `/themes`、`/ppt`、`/studio` 路径加载（`lazy`） |
| 主题库体积 | 36 套 × ~1.2 KB ≈ 45 KB（gzip ~12 KB）；P0 只加载 12 套原生（~15 KB） |
| 画廊渲染 | 一屏 ≤ 12 卡，`content-visibility: auto`；超过 24 套再上 `react-window`（已在依赖） |
| 切换主题 | 只改 CSS 变量，实测目标 < 16 ms，无重排整页 |
| 预览 | 纯 DOM/CSS，无 canvas / 无图片 / 无网络请求 |
| 导出 | 无新增网络；`theme1.xml` 序列化 < 2 KB |

## 11. 分阶段实施

### P0（约 4 天）—— "选得到、看得到、导得出"
1. `shared/deckTheme.ts`：类型 + `validateTheme()` + `themeToCssVariables()` + `buildPptxThemeXml()`
2. `themes/catalog.json`：12 套原生主题（手写）
3. `ThemePreview` 组件（复用真实版式，纯 CSS）
4. `/themes` 画廊（搜索/筛选/详情抽屉/应用到当前或新建）
5. `PptPage` 主题按钮 + CSS 变量注入；`PptProject.themeId` + 迁移

## 12. 验收标准（逐条可测）

1. **换主题不改内容**：切换前后 `slides.map(s => s.title + s.body)` 完全相等（单测断言）
2. **编辑时真生效**：`PptPage` 根节点 `--ppt-primary` 等于所选主题值
3. **导出真生效**：解压导出包，`ppt/theme/theme1.xml` 的 `accent1` == 主题 `primary`；首页背景色 == 主题 `primary`
4. **导出与预览一致**：同一 `slides + theme` 走 UI 预览与 PPTX，主色/底色/字色一一对应（有对照表测试）
5. **校验生效**：非法色值、超 4 KB CSS、含 `url(` 的 CSS 全部 400，并指出字段
6. **对比度提示**：低于 4.5:1 时出现 warning 且含真实比值
7. **迁移安全**：旧 `PptProject`（无 `themeId`）打开后颜色与之前一致
8. **首屏零成本**：`/themes`、`/ppt` 仍为独立 chunk，主包不增加
9. **派生幂等**：连跑两次 `build-theme-catalog.mjs`，`git diff` 为空

## 13. 风险与取舍

| 风险 | 缓解 |
|---|---|
| 24 套派生主题视觉同质 | ΔE 去重 + 人工淘汰，宁少不滥 |
| `theme1.xml` 与母版不一致导致 PowerPoint 显示怪 | 只用 clrScheme/fontScheme 两项，母版仍用默认；导出后回归测试 3 套主题 |
| 字体缺失 | 白名单 + 明确回退提示 + 预览用系统字体（预览即所见） |
| 自定义 CSS 成为注入面 | 仅 HTML 导出、禁 `url(`/`@import`、长度上限 |
| 主题数量膨胀拖慢画廊 | 分页 + `content-visibility` + 懒加载 |
| 与 180 套设计系统漂移 | 派生脚本 + CI 校验，catalog 改动会自动反映到主题 |

**明确不做**：主题市场交易、AI 生成主题（P3 再议）、PPTX 母版重建、字体子集嵌入。

## 14. 三个关键界面的走查（对照设计稿）

### 14.1 `/themes` 画廊（`01-themes-gallery.png`）

1. 顶部一句话定调：「主题」+「换主题不动内容」，右侧两个动作 `导入 PPTX` / `＋ 新建主题`
2. 筛选行为**即时**（搜索 + 风格 + 场景 + 排序），无"应用筛选"按钮 —— 与此前插件页保持一致的交互语言
3. 卡片 = 16:9 **真实版式预览**，下方是主题名 + 4 个色点 + 右下「应用」
4. hover 出 1px 紫边 + 「应用到当前演示稿」浮起按钮：**不点进去也能用**，这是 Gamma 效率感的来源
5. 底部常驻一行免责声明：「主题只管外观，不改变你的文字与结构」

### 14.2 主题编辑器（`02-theme-editor.png`）

- 三栏：左控件 / 中预览 / 右可访问性 + 应用到
- 预览上方 4 个 tab：封面 / 要点 / 图表 / 深色预览 —— 覆盖最容易翻车的三种版式与深色回退
- 中间黄条是**非阻断**警告：给出真实比值（3.9:1 < 4.5:1）与建议动作（加深 10%），右侧还有「仍要保存」
- 右栏把可访问性做成**逐项打勾**，而不是一句"符合 AA"
- 底部常驻「主题不改变文字与结构」，与画廊同一句，形成一致承诺

### 14.3 编辑器内的主题抽屉（未单独出图）

`/ppt` 工具栏点「主题」→ 右侧 380px 抽屉，与画廊同一批卡片但更紧凑（2 列），顶部一行显示当前主题名 + 「查看全部」→ 跳 `/themes`。
抽屉底部两个动作：`设为默认` / `新建自定义…`。**抽屉不遮挡画布左半边**，点卡片可即时看到效果。
