# 商业 PPT 引擎：首版实施与验收记录

日期：2026-10-19  
范围：获准实施方案中的 **P0 渲染/任务加固 + P1 首版生成链路**。这是可运行的首个里程碑，**不是完整方案已交付或商业视觉已验收的声明**。P2 专用编辑器/会话修订/版本对比没有实现。

## 1. 已落地的使用路径

在「技能」搜索 **商业演示** → 查看「商业演示AI规划与原生PPTX交付（首版）」→ 依赖就绪时打开执行工作台。

1. 填写目标、受众、场景、主题、8–25 页。
2. 选择 1–5 份 TXT / MD / DOCX / XLSX / CSV 来源，点击「准备演示输入」。此步骤只在浏览器内组装文件，尚不上传。
3. 分别确认「本次演示正文处理授权」和「同意后台上传并执行」，再启动运行。修改需求或材料会撤销已准备输入、上传同意及本次 AI 正文授权，重新准备后须重新确认两项授权。
4. 运行显示实际阶段事件，复用现有任务标识、账号隔离、幂等、运行列表、取消、下载和删除，不另建一套脱离任务系统的 PPT 应用。
5. 成果明确标记 **草稿**。任务执行完成与发布/商业验收是两回事。

`slides.create` 已接入真正的注册表、执行器、权限合同、运行时依赖检查、Worker 和 SkillService。它是手动提交的正文生成技能，不参与仅看文件元数据的旧路由规划；后者不能冒充读材料后的商业叙事规划。专家类别为 slides / infographics。

### 场景与主题

- 场景：商业汇报、融资路演、数据分析。目标与受众进入真实模型提示，不是只换封面标题。
- 主题：咨询米白/墨绿、企业蓝白、深色科技。颜色、字体和几何由确定性代码控制。
- 原生页型：封面、要点、指标卡、时间线、柱/折线图、逐字引语、两栏对比、可编辑表格。
- 单一受约束的内容规划调用，不是假装运行多个自主 Agent；最多一次来源/数据/格式校验重试。暂不做自动视觉重写。

## 2. 材料、模型与数值边界

### 输入和来源

- 每份材料 ≤2 MB，原始文件合计 ≤10 MB；JSON/base64 封装 ≤13.6 MB。
- 专用提交流量走现有 `/api/skill-runs?kind=presentation`，multipart 上限 13.7 MB。**普通技能仍然是单文件 2 MB、请求体 2.1 MB**，不能靠这个查询参数扩大普通技能的文件限制。
- 提取正文与表格序列化合计 ≤40000 字、≤1200 个段落/数据块。超限拒绝，不截断后声称读过全文。
- 每个 XLSX 读取全部 1–3 个可见工作表；每表 ≤500 数据行、20 列。拒绝隐藏表、公式/缓存公式结果、合并格、富文本、错误或链接单元格。OOXML 沿用现有安全检查。
- CSV 位置为跳过空行后的记录序号；DOCX 为提取正文段落序号，不是 Word 页码。DOCX 页眉/页脚/图片/批注不作为正文事实来源，并有明确警告。
- PDF、OCR、图片、旧 PPT 导入没有接入本次多材料链路；原有 PDF/OCR/PPTX 检查技能仍独立存在。

### AI 与可信编译

来源带稳定文件 ID、块 ID、定位信息、SHA-256；模型返回声明式 JSON 规划。模型不能提交代码、XML、模型端点/密钥或任意对象属性。

逐页内容经过独立 schema 检查，并要求 1–8 个实际存在的来源 ID。引语必须逐字存在于引用块。图表、表格、指标必须提供 **数据表 ID + 实际行号 + 字段名**，展示值由代码从材料重新读取，拒绝模型直接提供图表数列或指标值。

本版不做隐式分组/聚合、汇率换算或单位推断。图表仅接受明确的十进制数：绝对值 ≤1e12、小数 ≤12 位、有效数字 ≤15 位且十进制往返不丢失精度。图表标签和坐标格式保留小数，不再默认四舍五入成整数。Excel/原生图表内部仍使用 IEEE-754；指标显示会去掉单元格首尾空白，原始单元格保留在 bindings。

**引用存在不等于陈述被来源语义支持。** 模型仍可能错误解读材料或漏掉矛盾。本版只做字面数字警告、来源/单元格绑定和待补充项，不声称独立事实核查、完整冲突发现或商业研究已完成。

### 模型部署

需要在服务端配置 `AI_API_KEY` 或 `OPENAI_API_KEY`，可选 `AI_BASE_URL`、`AI_MODEL`（兼容既有 `OPENAI_MODEL`）。新流程调用既有模型适配器的 `serverConfigurationOnly` 模式：

- 没有显式环境凭据就拒绝，不使用仓库既有其他调用路径的内置回退配置。
- 没有配置 base URL 时，明确默认 OpenAI `https://api.openai.com/v1` 和 `gpt-4o-mini`，不会把 OpenAI key 自动送往其他默认网关。
- 不接受材料或每次请求中的 provider/key/baseUrl/model 覆盖。
- 单次模型调用 60 秒、响应流 ≤1 MB；最多两次规划调用，不对提供商错误自动重发。
- 使用量来自服务商实际报告，Worker 绑定当前运行所有者交回既有用量记录器；不估算余额、token 或费用。检查点保存已有用量，恢复不重复计入模型调用。

当前聊天模型选择与此服务端正文通道不是同一项配置。提供商留存/训练政策需部署者明确，并在真实材料验收前确认。本轮没有配置或调用真实外部商业模型；协议端到端测试使用本地测试提供商。

## 3. 输出、任务恢复与资源限制

成功编译的任务包含：

- `draft-presentation.pptx`：原生文字、形状、原生图表及其可编辑工作簿、表格、讲稿；不是逐页位图。
- `draft-presentation.pdf`：同一 PPTX 经本机 LibreOffice 真正导出并检查物理页数，导出通过时才出现。
- `rendered-slides.zip`：全部页面 960px JPEG、渲染清单、字体许可与人工复核提示。
- `slide-contact-sheet.jpg`：全页联系表。
- `render-report.json`：真实引擎、页数、字体和页图证据；失败也输出明确的失败记录。
- `presentation-spec.json`：需求、内容版本哈希、逐页规范、真实模型标识/用量、是否从检查点恢复、未实现的修订能力说明。
- `sources-and-notes.json`：来源全文/数据、定位与哈希、逐页来源引用、真实单元格绑定和讲稿。
- `resolved-layout.json`：稳定页/文字元素 ID、文字和表格单元格的固定字号、英寸几何。
- `quality-report.json`：独立质量状态、问题、未检查项、字体及文件哈希。
- 现有 `execution-receipt.json`：绑定任务/运行、技能版本、权限、输入哈希及执行事件。

最多 10 个成果（含 receipt）、演示输出合计 ≤25 MB，所有者仍 ≤100 MB、全局 ≤1 GB；沿用每账号 100 次记录、全局 20 个待处理运行和现有提交次数限制。两名后台 Worker；没有取消总配额。

时间预算按技能限定：普通技能原有 45 秒；PPTX compose/inspect 默认 150 秒，覆盖内部 90 秒渲染；`slides.create` 默认总计 300 秒，内部模型与 PDF/位图阶段各有时限。测试注入的自定义较短期限不被无条件放大。

规划完成后通过独立的 `skill_presentation_checkpoints` 表持久化，**没有混用 OCR 的页/PNG 检查点**。检查点绑定输入 SHA-256、版本、阶段与 schema，≤400 KB，UTF-8 字节计入所有者/全局存储。取消或失败保留规划；重启和显式继续仅复用已有规划，重新编译/渲染，不再发送正文或调用模型。没有已保存规划时拒绝 resume，必须重新明确授权新建，避免未知外部请求被静默重放。

最终成果在事务中原子发布，再清除规划检查点；删除运行级联清除输入、成果和检查点。服务创建的 PPTX 临时目录由父进程持有，正常终止/取消/close 后清理。整个主机进程崩溃时遗留的系统临时目录仍需部署环境常规清理；这不是跨机器分布式队列或通用沙箱。

## 4. 字体与质量状态

LibreOffice Kit **0.2.0 已从开发依赖提升为生产依赖**。Linux 仍需要它的平台 WASM 包，macOS/Windows 需要对应引擎；缺依赖明确禁用。

`assets/presentation-fonts` 内提供 OFL 许可的 Noto Sans SC 常规 400 / 粗体 700 两个静态实例，校验 SHA-256，并限制渲染字体目录/文件/加载字节。提供可复现的 FontTools 4.60.1 构建脚本及上游 Git blob 溯源。生产部署须保留该目录；运行时不下载字体。PPTX 没有内嵌字体，接收方仍须安装 Noto Sans SC。

质量报告只会给出：

- `blocked`：缺字/字体缺失、越界、过密、文字框交叠、已知背景对比不足、页数错误、PDF或全页渲染失败等关键问题。只允许明确标记的草稿和诊断下载，不能视为正式稿。
- `needs-human-review`：已执行规则没有发现 critical，但依然需要人工验收。

`commercialApproval` **始终为 false**。文字度量使用实际常规/粗体字体，但仍是保守估算，不是 Office 的原生断行证明。`resolved-layout` 只覆盖文字与表格单元格，不谎称覆盖图表内部标签或全部装饰形状。原生图表标签碰撞、完整遮挡、审美质量、来源语义、版权、目标软件重新打开编辑等明确列入 `notChecked`。不会通过不断缩字或删事实来消掉告警；尚无自动视觉修复。

## 6. 可下载样本与复现

样本包：[commercial-ppt-samples.zip](examples/commercial-ppt-samples.zip)（约 637 KB）。

三套各 8 页，包含 PPTX、实际 PDF、全页 JPEG/联系表、输入、来源/数据绑定/讲稿、规范、文字几何与质量报告。`manifest.json` 列出文件 SHA-256。三个样本都是 `needs-human-review`、0 critical、`commercialApproval:false`。

**样本使用 CC0 合成数据和固定逐页规划，未访问真实模型，不代表三个真实商业项目、三份不同市场研究或 AI 叙事质量已验收。** 三者共用可核对的数据骨架，用于验收编译、主题、可编辑对象、来源链和真实导出。下一阶段仍需要有授权的实际业务材料与真实模型返回，逐项核对事实和商业叙事。

```sh
corepack pnpm exec tsc -p server/tsconfig.local.json
node scripts/generate-presentation-samples.cjs
```

字体溯源、哈希和复现说明：[assets/presentation-fonts/README.md](../assets/presentation-fonts/README.md)。
