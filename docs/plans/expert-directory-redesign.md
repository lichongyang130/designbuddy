# 专家目录重建（2026-10-15）

## 已实现

以首页三个业务方向为唯一内置分类，不使用学历、机构品牌或泛化头衔填充角色：

| 方向 | 四位核心专家 |
| --- | --- |
| 办公提效 | 文档整理专家、数据分析专家、汇报提案专家、工作协作专家 |
| 设计制作 | 品牌视觉专家、营销物料专家、产品展示专家、信息可视化专家 |
| 网页应用 | 产品需求专家、网页交互专家、全栈开发专家、测试验收专家 |

- 唯一源 `shared/expertRouting.ts`，`expertCatalog.ts` 仅派生 UI 属性；首页匹配与手选共用它。旧高校、升学、求职、泛资讯及机构背书角色不再是内置候选。
- 数据分析核对口径和事实；信息可视化负责可读性；汇报提案组织论证与决策表达，不再互相混为一谈。
- 列表有全部、三方向、我的专家五个过滤项及搜索；卡片包含职责、适用任务、工作方法、交付物，以及详情/选用动作。
- 详情包含材料、步骤、交付、验收、真实能力边界；36 个示例均引用首页现有任务 ID，不复制一套提示词。全部 30 个首页类别都有专家覆盖。
- 移除无关专题、专家团入口、假热度与使用人数。仍只选一位主专家，不提供虚构协作与工具执行。
- 每个选用动作回到首页锁定专家；仅选专家不修改草稿、附件、模型、空间和权限。使用任务示例会请求覆盖非空草稿，确认后填入完整提示词，取消时原专家与草稿不变，均不自动发送。
- 首页推荐/已选专家面板可以查看对应详情。原自动匹配同意、关闭、仅本地、异步失效和错误处理规则不变。
- 自建专家与历史任务无迁移、清空或删除。自建专家和内置同名时仅添加显示后缀，不改存储记录。旧 developer/product 详情路径对应相近的新角色，其余已下架路径明确提示不可用。
- 保留首页与共享侧栏现有外观、输入框向下自适应、横向专家标签、弹窗关闭行为。手机详情将主动作独立成行，避免挤压标题。

## 本次验证

- 前端 TypeScript 与生产构建通过；服务端 TypeScript 通过。
- 目录专用 Node 测试 3 项：12 位/每方向 4 位，覆盖 30 类，36 个示例全部存在且与方向/类别一致，材料/方法/验收规范和能力限制齐全。

- 检查 320/375/768/1440 宽度，目录与详情无页面横向溢出；实际查看桌面目录及手机详情截图。
- 自动匹配测试使用受控响应；当前没有配置真实 AI 服务，不能据此声称真实模型的识别准确率或工具执行能力已经验证。
