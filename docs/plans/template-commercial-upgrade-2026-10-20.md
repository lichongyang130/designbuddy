# DesignBuddy 模板商业级升级方案（待确认）

日期：2026-10-20  
用途：应用内置模板升级与扩充，不涉及外部社区发布。  
本轮交付：分类方案、内容范围、交付格式、验收与实施顺序；不修改应用、不生成付费素材、不接入外部业务系统。

## 一、结论

采用“两级分类、三种能力标识、逐套验收”的方案：

1. 一级沿用应用正在使用的 9 类产物：原型、幻灯片、文档、图片、HyperFrames、视频、音频、实时产物、WebGL。
2. 二级使用行业/用途标签，与现有商业目录的 19 个类别建立映射，而不是把两套目录数字相加。
3. 商业级不是更多卡片或统一增加到 24 页，而是：内容完整、视觉有辨识度、关键交互可用、可修改复用、导出真实可开、素材来源可追溯、边界诚实。
4. 优先补齐已展示的模板；建议新增 18 套（每类 2 套），逐套通过验收再上架。18 是本方案建议，不是已完成数量。
5. 不把“商业模板可交付”与“真实支付、生产订单、多用户实时服务已上线”混为一谈。后者单列系统集成，需真实权限、配置和验收。

## 三、商业级的共同要求（建议验收标准）

这些是项目拟采用的内部标准，不是已经取得的行业认证，也不是已完成结果。

### 3.1 内容

每套需有：受众、业务目标、适用范围、完整样例、输入字段、字段解释、数据来源/模拟标识、输出说明、限制说明。

- 不保留 Lorem、TODO、无意义占位或重复页面凑数量。
- 虚构品牌和样例数据清楚标识；不伪造客户证言、销量、疗效、收益、市场统计、签约案例或真实机构背书。
- 每个页面/画板/片段有明确作用：用户要完成什么、正文是什么、证据是什么、下一步是什么。
- 表格写清字段意义、单位、币种、时间范围、计算口径；总计可复算。
- 页数、时长、分辨率按任务需要确定，不统一硬凑 24 页。

### 3.2 视觉

- 每套有独立的字体、颜色、栅格、图像方向和关键版式，不靠同布局换色形成新模板。
- 使用统一的设计 token，但允许不同领域形成不同视觉性格。
- 完整设计正文、图表、表单、空态、错误态，而不只设计封面。
- 主视觉与主题相关，保证素材授权与可替换性；不自动购买素材或调用尚未选定的付费生图供应商。
- 建议测试 1440、1024、768、390 CSS px 等典型视口，并检查长中文、长英文与缩放；这是待执行测试矩阵。

### 3.3 交互与复用

- 关键操作真实执行，失败有反馈，不用“点击成功”的 toast 代替保存、导出或提交。
- 区分示例原件与用户副本；修改/重置/刷新/重新打开的行为一致，不覆盖他人副本。
- 可更换品牌、文案、数据、图片与主题的范围写清；不可编辑项不得标为可编辑。
- 无障碍包含语义、键盘流程、焦点可见、错误提示、对比度检测与减少动态效果设置。

### 3.4 导出与授权

- 导出文件必须真实生成、能打开，并与预览的内容版本一致。
- 只有真实支持的格式才出现下载按钮；截图不冒充可编辑 PPTX/DOCX/源文件。
- 字体、照片、插画、音乐、模型、代码分别登记来源与许可；未知许可是交付阻断项。
- 没有接入的邮件、支付、交易、预约、实时 API 等持续显示边界，不通过删提示伪装上线。

## 四、按 9 类制定升级与新增方案

以下全部为拟建设内容与交付目标；实际导出能力需逐套实现与验证。

### 4.1 原型：从浏览演示升级为任务闭环

**已有 8 套逐项补齐：**

| 主题 | 重点内容与交互闭环 |
|---|---|
| 旅行预订 | 目的地与日期筛选 → 方案详情 → 行程编辑 → 费用解释 → 预订意向；无真实供应商时不创建正式订单 |
| 展馆预约 | 展览/场次/规则 → 人数与信息校验 → 时段冲突 → 预约草案 → 修改/取消；真实容量另接后台 |
| 家具采购 | 规格/材质/尺寸 → 选配 → 空间清单 → 报价明细 → 采购方案导出 |
| 服饰订制 | 款式/面料 → 量体输入 → 尺寸校验 → 工艺单 → 试衣修改记录 |
| 花园规划 | 环境输入 → 植物筛选 → 分区布置 → 土水预算 → 养护日历 |
| 联合办公 | 空间/工位 → 时间选择 → 冲突提示 → 团队方案 → 费用与 ICS；本地冲突不冒充全平台可用性 |
| 帆船会员 | 会员方案 → 时间意向 → 时数规则 → 课程记录 → 费用；不声称已确认出航或天气安全 |
| 咖啡订阅 | 偏好 → 拼配与冲煮 → 四期计划 → 费用 → 修改/暂停意向；不创建实际扣费 |

**建议新增两套：**
- 企业 CRM：线索、公司、联系人、商机阶段、跟进记录、报价草案、漏斗分析；统一假想客户数据。
- 精品酒店直订：房型比较、日期/入住人数、房态演示、套餐解释、预订草案、入住指引。

**交付目标：**应用内可编辑副本、可运行网页/源码包，以及适用的 CSV/JSON/ICS；交互原型与生产后台分别标识。

### 4.2 幻灯片：从视觉样例升级为可演讲、可编辑的业务表达

现有 5 套按用途区分：领导决策必须有建议/证据/取舍/风险/下一步；城市提案必须有路线、资源、预算口径和执行；内容导演/视觉方向保留同内容比较能力，不只做风格封面。

**建议新增两套：**
- B2B 产品销售提案：客户问题 → 解决方案 → 工作机制 → 场景 → 实施范围 → 交付物 → 商务假设 → 决策行动。禁止虚构客户案例与 ROI。
- 季度经营复盘：目标口径 → 实绩 → 差异 → 驱动因素 → 专题分析 → 问题归因 → 下季行动 → 决策事项；样例数据与计算表同源。

**内容规格：**每页包含页级目标、正文、来源/假设、图表选择、讲稿；原生可编辑图表/表格优先。页数由表达任务决定。

**交付目标：**PPTX + PDF + 预览图 + 来源/假设清单 + 讲稿；实际渲染检查溢出、遮挡、图表文字、导出一致性。先重排、简化内容再处理字号，不以持续缩字掩盖密度问题。

### 4.3 文档：从排版演示升级为可交付文件

现有研究报告补来源、方法、局限与结论对应；旅行手册补输入条件、清单、预案及更新日期；Word 专业排版扩充真实表格、附录、图题、目录与修订情景。

**建议新增两套：**
- 项目实施方案：背景、目标、范围/不含项、交付物、里程碑、角色责任、验收、变更、风险与附录。
- 企业 SOP 手册：适用范围、角色、前置条件、操作步骤、判断分支、异常升级、记录表单与版本修订。

**交付目标：**DOCX + PDF + 样式/字段说明；真实分页、目录、表头、跨页表格、页码、页眉页脚分别验证。DOCX 结构检查与实际渲染检查都要执行，不能用浏览器打印替代 Word 交付验收。

### 4.4 图片：从单张设计图升级为成套传播资产

- 保留已经交付的 15 套欢迎页和独立主视觉，不重新生成、不更改当前登录页布局。
- 将其清楚标为登录/欢迎页设计参考；如以后做可编辑 UI 套件，作为独立建设项，不声称现有 PNG 有可编辑图层。
- 迟山与自然系列补充尺寸适配、标题层级、长短文案、印刷/屏幕使用范围和品牌规则。

**建议新增两套：**
- 新品发布视觉包：主海报、产品卖点、细节、价格/规则、倒计时、社媒卡片、横幅与封面。
- 商务活动传播包：邀请、日程、嘉宾、报名指引、会场导视、倒计时与复盘图。

**交付目标：**PNG/JPG + 真实支持的 SVG/可编辑布局 + 尺寸与安全区说明 + 素材许可。常用比例按具体渠道确认；不承诺固定平台规范永久有效。没有印刷色彩/出血校验时不标“印刷就绪”。

### 4.5 HyperFrames：从动画片段升级为叙事与操作引导

已有品牌分镜、功能导览、数据故事、剧情、微课分别补完整时间线、可编辑台词、图表/事件联动、分支回退、学习反馈。

**建议新增两套：**
- SaaS 产品上手导览：任务引入 → 功能聚焦 → 操作指引 → 结果反馈 → 下一步。
- 品牌滚动叙事：问题 → 产品细节 → 差异点 → 使用场景 → 行动入口；样例主张显式标注。

**交付目标：**交互 HTML/CSS/JS 包、时间轴/分镜数据、动效参数、减少动态效果版本；保持键盘可操作与跳过。默认不承诺导出视频，录制/编码作为另外的验证流程。

### 4.6 视频：从单个短片升级为可复用剪辑方案

现有 LAKESIDE 保留摄影风格，补镜头用途、素材索引、字幕规范、转场、片尾/品牌区和横竖版裁切检查。

**建议新增两套：**
- 产品演示短片：问题场景 → 产品展示 → 功能演示 → 使用前后对照 → 行动入口。
- 活动回顾短片：开场 → 场地/人物/互动 → 重点信息 → 收尾；不虚构真实到场规模或嘉宾身份。

**交付目标：**实际编码的 MP4、VTT/SRT 字幕、分镜表、素材清单、可重建时间轴配置（JSON，不冒称 Premiere 工程）。素材/音轨权利、时长、分辨率、黑帧、字幕安全区、音画同步与播放逐项验收。没有合法音源时允许无音乐版本。

### 4.7 音频：从合成声音样例升级为可复用声音资产

现有 SOFT SIGNALS 补用途说明、响度/峰值检查、淡入淡出、长度变体和无障碍提示；不以品牌声音样例冒充正式品牌授权。

**建议新增两套：**
- 播客包装：片头/片尾、章节转场、主持口播示例、节奏和文件命名规则。
- 产品提示音：成功、提醒、警告、错误、完成等差异化声音，配静音与视觉等效反馈。

**交付目标：**WAV + 适用压缩试听文件 + 参数/脚本 + 用途/权利说明；采样率、声道、峰值、裁切和淡入淡出实测。语音、合成音效、音乐是不同能力；音乐需合法来源或指定生成供应商，不能用朗读代替。

### 4.8 实时产物：从本地演示升级为可信的小工具

- 报价：字段口径、币种、税率/折扣顺序、金额舍入、版本与导出核对。
- 大屏：数据源说明、指标定义、时间范围、加载/断线/无数据/过期状态。
- 活动：报名/签到字段、隐私说明、去重、导出；抽奖规则和随机性边界。
- 问卷：题型、校验、匿名说明、样本数和分母定义、导出。
- 状态页：真实/演示模式区分，事件时间线、时区、指标计算口径与不可用状态。

**建议新增两套：**
- 项目成本测算器：人员、工时、单价、外采、税费、风险准备金、情景对比；公式可复算。
- 活动报名与签到工作台：表单、校验、名单搜索、重复提示、签到状态与导出；先实现本地/受控样例闭环。

**交付目标：**可运行网页、CSV/JSON、字段字典与公式说明。多设备同步、真实提交、持久化和审计属于单列服务接入；未接入时保留“本地/演示”标签，不能通过删掉标签称为实时商业服务。

### 4.9 WebGL：从单个材质场景升级为产品可视化模板

现有“材质与光”补相机重置、模型加载、旋转/缩放边界、移动端操作、材质切换、异常和静态降级。

**建议新增两套：**
- 家具/产品 3D 配置器：模型、颜色、材质、尺寸参照、视角、配置清单与截图。
- 展厅/展台预演：布局分区、灯光方案、热点说明、相机预设、方案对照。

**交付目标：**可运行 WebGL 网页与配置、合法模型/纹理、实际支持格式的模型文件或导入说明、静态后备图。没有经过尺寸/物理校准时不得用于工程测量或声称真实物理效果；不统一承诺不存在的 glTF/OBJ 导出。

| data | 数据工作台 | 2 | 数据字典、导入验证、质量、表格/图表联动 |
| security | 身份与安全 | 2 | 角色、访问规则、审计、隐私与拒绝路径；不宣称合规认证 |
| support | 客户支持 | 1 | 工单分类、优先级、分派、回复、升级、关闭与重开 |

每个系列先明确自己的核心任务与页面图，再设计页面。允许共用表格、筛选、表单等基础组件，但不允许 130 套都只换标题并复用同一套 24 页目录。

## 六、每套必须留下的交付包

1. 模板说明：名称、行业、受众、目的、能力范围、数据模式、支持格式。
2. 内容清单：每页/画板/片段/状态的目标、正文、输入、证据、输出、备注。
3. 可编辑内容或运行源码：明确支持编辑的字段与不支持的边界。
4. 已验证导出：文件、预览、软件/浏览器打开证据；不支持的格式不伪造。
5. 素材与许可：来源、许可、字体、署名、替换方法、禁止用途。
6. 测试记录：交互、持久化、异常、无障碍、响应式、导出；含实际结果和待完成项。
7. 版本与迁移说明：模板原件、用户副本、升级兼容与回退。

建议卡片显示三个独立维度：
- 数据模式：样例 / 本地计算 / 已连接服务。
- 复用能力：仅参考 / 可编辑 / 可运行。
- 验收状态：未验收 / 部分通过 / 已通过（附证据与版本）。

不要用单个“商业版”徽章掩盖数据模式与交付能力差异。

## 七、验收：硬性失败不能被视觉评分抵消

| 检查层 | 通过条件示例 | 不通过的处理 |
|---|---|---|
| 内容 | 场景完整、口径一致、样例标识和来源齐全 | 退回补内容 |
| 视觉 | 无遮挡/溢出/缺字、层级明确、主题相关 | 调整布局后重新渲染 |
| 交互 | 主流程、取消、校验、空态/错误态实际可执行 | 阻断上架，不靠成功 toast 代替 |
| 数据 | 公式可复算；保存/重开一致；按承诺的隔离范围测试 | 修复后重新验收 |
| 导出 | 文件可开、内容版本一致、承诺的可编辑性成立 | 移除未支持格式或补齐实现 |
| 可访问性 | 自动检测与键盘人工流程均有证据 | 修复高严重问题后再验收 |
| 许可与真实性 | 权利来源明确，无虚假服务、背书或业务状态 | 作为硬性阻断 |

PPT 与 Word 的验收分别执行，不共享一个“Office 导出成功”结论。真实服务集成需要另外验证授权、错误、超时、重复提交、隔离、日志脱敏与重启恢复。

## 八、实施次序与审阅节点

### 阶段 A：清单与去重

- 优先处理空内容、失效资源、虚假按钮、错误能力标识等阻断问题。

### 阶段 B：9 类各完成一个标杆

建议标杆：家具采购原型、季度经营复盘 PPT、项目实施方案 DOCX、新品发布视觉、产品导览 HyperFrames、产品演示视频、产品提示音、成本测算器、产品 3D 配置器。

### 阶段 C：补齐存量、交付建议新增 18 套

- 对 46 个已有展示条目逐套升级与验收。
- 对每类建议新增的两套，按独立主题与业务内容交付，不以同内容换色凑数。

### 阶段 D：系统接入与正式部署

真实支付、邮件、预约、数据源、多端实时同步、音乐/生图服务等分别明确供应商、权限、成本与验收，再实施。未具备条件的继续作为清楚标识的本地模板，而非假装接通。

提供模板 ID 清单、实际截图/导出、测试结果、未完成事项及 Git 提交；经确认再发布到正式服务器。源代码保存到固定分支，密钥、用户数据库、缓存及大体积发布包遵循现有忽略/外部存储规则。
