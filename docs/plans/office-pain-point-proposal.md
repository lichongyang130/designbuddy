## 重构原则

一级保留“文档处理、图像创作、数据分析、PPT制作、智能助手”。二级栏目不再使用“总结提炼、撰写编排”等工具术语，而是命名为用户遇到的工作困难；热门列表项则命名为解决这个困难的具体任务和交付结果。

层级示例：文档处理 → 开完会议难整理 → 把讨论记录整理成决策、待办和责任人清单 → 填入完整提示词。

## 建议栏目

### 文档处理：减少阅读、写作和核对成本

| 二级痛点栏目 | 热门任务示例 |
| --- | --- |
| 长文太多读不完 | 把长报告压缩成一页摘要；从制度文件提取与我有关的要求 |
| 开完会议难整理 | 整理会议结论与待办清单；从访谈记录归纳需求与争议 |
| 报告周报写不快 | 用零散工作记录生成周报；把项目材料组织成汇报初稿 |
| 文案表达不专业 | 把口语化草稿改成商务表达；校对中英商务文案的含义和语气 |
| 多版文档难核对 | 对比两版内容的新增、删除与修改；检查全文日期、数字和术语一致性 |

### 图像创作：降低办公视觉制作门槛

| 二级痛点栏目 | 热门任务示例 |
| --- | --- |
| 做图不会排版 | 把活动信息整理成海报版式；为通知设计清晰的信息层级 |
| 汇报配图不好找 | 为报告提出匹配主题的配图方案；把复杂流程转成可制作的示意图说明 |
| 活动宣传赶时间 | 编排活动预告图的文案与构图；规划同一活动的系列宣传画面 |
| 产品卖点说不清 | 把产品特点转成视觉卖点卡片；规划产品使用场景展示图 |
| 多个平台改图累 | 制定横版、竖版和方图适配方案；规划多尺寸裁切与文字安全区域 |

图像相关任务必须根据真实工具能力交付。没有图像解析、生成或编辑工具时，明确交付构图、文案、规格与制作提示词，不声称已读图、已修图或已生成可下载图片。

### 数据分析：把表格变成可解释、可行动的信息

| 二级痛点栏目 | 热门任务示例 |
| --- | --- |
| 表格太乱不好用 | 检查重复、缺失与格式问题；统一日期、单位和字段口径 |
| 数字变化解释不清 | 拆解销售额变化的构成；分析费用增长主要来自哪里 |
| 业绩下滑找不到原因 | 按渠道排查转化下降；检查用户流失集中在哪类群体 |
| 多张表总是对不上 | 核对两份名单的差异；定位明细合计与汇总数据不一致的原因 |
| 有数据不会做汇报 | 整理管理层最关注的三项发现；为指标选择图表并写清结论与限制 |

必须先检查材料能否实际读取；当前对话无法解析的文件应要求转成支持的文本/CSV 等形式，不能根据文件名猜测内容。

### PPT制作：解决内容组织与汇报表达问题

| 二级痛点栏目 | 热门任务示例 |
| --- | --- |
| 汇报没有故事线 | 把散乱素材组织成完整汇报逻辑；把项目材料转成问题、证据和行动顺序 |
| 材料太多塞不下 | 将长文材料压缩成十页重点；区分主讲内容、附录和可删除内容 |
| 向领导汇报抓不住重点 | 整理三分钟决策简报；突出结果、风险与需要支持的事项 |
| 方案提案说服力不足 | 比较备选方案与关键取舍；把功能罗列改成价值与证据表达 |
| 页面太乱看不下去 | 拆分文字密集页面；为每页安排标题、主结论、图表和讲解备注 |

仅提供大纲时不能称为已制作 PPT 文件；需逐页内容、排版、图表与讲解备注，真实文件交付依赖已接通的导出能力。

### 智能助手：解决任务推进、沟通和取舍问题

| 二级痛点栏目 | 热门任务示例 |
| --- | --- |
| 任务太多排不过来 | 按期限、影响和投入排列优先级；把目标拆成今天能执行的步骤 |
| 跨部门事情推不动 | 梳理依赖、责任与待协调事项；准备推进会议的议程和决策问题 |
| 催办拒绝不好开口 | 起草礼貌催办消息；写清拒绝或延期原因及替代安排 |
| 选方案总是拿不定 | 按真实目标建立比较表；列出决策缺失信息与验证方法 |
| 临时接任务不知怎么做 | 把模糊指令转成需求确认清单；规划第一小时行动和最终验收标准 |

与文档处理分工：文档处理以材料加工和正式文档为核心；智能助手以优先级、协作、行动路径和即时沟通为核心，不重复堆放相同条目。

## 提示词标准

- 每个二级栏目先规划 8–12 个真正不同的任务，再扩充；不要靠改标题制造数量。
- 每条提示词至少 200 个中文字，建议 300–600 字；不靠重复公共免责声明凑字。
- 包含：工作情境与目标、需要的材料、明确处理步骤、指定交付结构、事实/权限边界、检查标准、材料不足时的提问方式。
- 用任务特有的验收细节区分条目，如会议纪要必须区分决定与建议，数据报告必须定义分母与时间范围，PPT 必须逐页说明主结论与讲解内容。
- 没有信息就询问，不虚构数据，不把建议冒充真实操作或已生成文件。

## 推荐与交互

维持“分类 → 痛点 → 具体任务列表 → 完整提示词”流程。

推荐优先级：所选痛点相关性 → 当前输入关键词 → 本机使用偏好 → 本轮尚未看过的任务。换批不跨痛点凑数，不自动覆盖输入或发送任务；同一轮看完后可重新排序，但不假装无限生成了新场景。

首轮先重构日常办公模式的 25 个痛点栏目。代码开发与设计创意模式不因本方案而被改为办公栏目。
