## 一、建议结论

继续复用现有「授权材料 → 逐页规划 → 原生 PPTX → 同文件 PDF/全页渲染 → 质量报告」底座，优先补齐：

1. **真实模型自动规划的可验证质量**：先确认没有助手预编排时，也能从授权材料产生可用的故事线与实质正文。
2. **内容自适应版式**：由固定八种页型，升级到语义页型与视觉布局分离，避免每页都变成四条要点或上半屏小表格。
3. **原生图表、品牌和安全素材**：保留编辑性，让数据与重点更清晰，而不是用整页图片掩盖布局问题。
4. **有边界的质量修复与局部修改**：保留事实和数据绑定，允许换布局、调整留白、明确拆页、修改目标页，防止整套稿反复重写。

第一批建议只批准 **M0 + M1**：真实规划基准、布局底座和领导决策汇报的版式升级。M2、M3 在可观察效果达标后继续。不先建设复杂多 Agent 系统，不先承诺任意旧 PPT 无损编辑。

## 二、当前起点：哪些可复用，哪些还欠缺

| 层面 | 当前有事实支持的能力 | 仍需补齐 |
|---|---|---|
| 输出 | 原生文字/形状/柱状与折线图/表格/讲稿；真实 PDF、全页 JPEG | 更多数据表达、图文版式、品牌系统与应用端编辑验收 |
| 主题和页型 | 三组固定主题、八种原生页型 | 主题参数化、同页型多布局、密度适配及整套节奏 |
| 内容 | 有 `slides.create` 规划协议、来源和字段绑定、有限结构纠错 | 真实服务端模型与实际业务材料的叙事/事实质量验收 |
| 本次案例 | 助手按源码证据编排的 12 页案例，实际调用项目编译和导出 | 不能把它当成后台外部模型自动达到同等水平的证明 |
| 检查 | 字体、文字几何、密度、文字框交叠、对比度、实际页数等检查 | 完整对象遮挡、图表内部标签、视觉层次和语义支持度 |
| 使用 | 通用执行台、内置案例翻页与下载、显式新建入口 | 持久演示工作区、单页修改、布局切换、版本回退 |

历史回归与本次案例回归的范围分别见原记录；本方案没有重新运行测试，也不将原结果包装成升级已完成。

## 三、用户最终应当看到的工作流

填写用途、受众、时长/页数与风格 → 选择并授权材料 → 先审阅故事线及缺失证据 → 生成真实页面 → 按页切换布局或修改内容 → 重新导出和检查 → 人工确认交付。

- 不要求用户先写结构化 JSON。
- 模型负责理解和选择受支持的表达，不输出可执行 JS/XML 或任意坐标代码。
- 所有数值来自实际字段绑定或明确、可追踪的代码计算，不由模型自由填入。
- 浏览器交互预览与 LibreOffice 实际渲染分开标注；只有后者可称为该导出文件的渲染证据。
- 浏览器修改先写入文稿新版本，重新编译、渲染、检查后才生成对应下载文件。

## 四、M0：建立真实自动规划基准

### 目标

回答当前最重要的未验证问题：**不用助手预先写好逐页内容，系统能否从真实材料自动产出清晰的汇报？**

### 实施内容

- 使用已授权、可追溯的材料，先沿用本次「PPT 引擎是否进入试点」题材作为对照。
- 在服务端模型配置和单次正文授权就绪后，实际运行 `slides.create`。不因要测试而读取/更换隐含凭据，也不绕过授权。
- 保存规划返回、通道/模型标识、来源位置、实际用量、失败原因和文件版本；未报告用量不猜测价格。
- 引入逐页内容检查项：结论、证据、分析/建议、正文、图示意图、讲稿、待确认项。
- 数字绑定、引语、来源 ID 仍由确定性代码验证；可选模型评审只提供意见，不能独立认定事实正确。
- 给失败分类：材料不足、结构不合法、缺证据、叙事薄弱、导出失败。不能全部归成“再试一次”，不能用固定案例偷偷替换失败结果。

### 交付与验收

- 同一资料下的「助手编排基线 / 真实自动规划」独立版本，明确注明生成方式，不混淆成排版效果对比。
- 每页有实质内容，不用目录替代正文，不编造预算、收益、日期或人员。
- 材料缺失、相互冲突时能明确保留待确认项；来源存在不等于语义必然受支持。
- 若真实模型不稳定，先改善规划合同、证据组织和受控纠错，不以堆模板掩盖。

## 五、M1：优先交付肉眼可见的版式升级

### 1. 将“讲什么”与“怎么排”分开

现有 `PresentationSpec` 继续记录内容与来源。新增受版本管理的布局规则，在模型选择表达意图后，由代码根据文本长度、元素数、图表/表格规模和画幅选择兼容布局。

建议结构：

```text
证据与字段绑定
      ↓
内容文稿（语义、结论、讲稿、来源）
      ↓
布局意图 + 布局规则目录 + 主题令牌
      ↓
ResolvedLayout V2（所有受支持对象的明确几何与标识）
      ↓
原生 PPTX 编译 → 同文件 PDF / 页图 → 规则检查 / 人工复核
```

这是拟议结构，不是当前编译器可直接接收的新 JSON。需要版本化解析、旧文稿迁移和兼容测试，不能直接给旧 schema 增加未知字段。

### 2. 首批建议交付 12 套实用布局

这里的“12 套”是建议工作范围，不表示现有八种页型之外已经增加了十二种新页型。

| 布局 | 肉眼可见的变化 | 证据/编辑边界 |
|---|---|---|
| 结论型封面 | 主结论、决策对象、状态和必要背景层次分明 | 不把“建议”排成“已批准” |
| 执行摘要 | 一句话建议 + 核心依据 + 待拍板事项 | 无依据的数值不进入摘要 |
| 决策选项矩阵 | 多方案同屏；推荐方案清晰突出 | 不生成无依据评分或 ROI |
| 能力/边界对照 | 已实现、未实现、未验收分别呈现 | 不把规划当作完成事实 |
| KPI 与解读 | 指标、口径、核心含义联动 | 不混算不同范围的通过率 |
| 图表 + 结论 | 图表区、解读区、口径区合理分配 | 图表保持原生；文字可编辑 |
| 图表 + 数据明细 | 一眼看趋势，仍能核查具体单元格 | 共享同一绑定和转换记录 |
| 自适应表格 | 按列宽和内容重排，不再小表塞上半屏 | 不隐藏行或删减事实消除溢出 |
| 风险与应对 | 风险、触发条件、动作、责任状态分层 | 概率、损失与负责人不凭空补齐 |
| 路线图/关卡 | 依赖、阶段和通过条件更清楚 | 无排期依据时不编造日历日期 |
| 证据截图 + 说明 | 产品/流程截图配可编辑结论和标注 | 截图内容本身不承诺可编辑 |
| 行动/审批结尾 | 决策项、待确认项与下一步一眼可见 | 不能自动生成批准记录或签名 |

### 3. 密度适配与整套节奏

- 不再把所有页固定为相同的卡片高度、表格行高和文本区位置。
- 先尝试兼容布局和合理列宽，再调整图文占比与留白；保留明确字号层级，不通过反复缩字消掉问题。
- 正文建议优先采用适合投屏的字号；页脚来源与密集表格另设规范，不把备注的小字标准套给正文。
- 超出用户页数时先提示并给出拆页方案。未经确认不默默增加页数、不删正文、不省略表格行。
- 章节起承、证据页、比较页和结尾使用不同视觉节奏；没有必要时不强行插目录或大图。
- 同一份文稿更换主题不更改事实、计算结果、来源绑定或“建议/事实”的性质。

### 4. 用现有领导决策案例作效果验收

固定相同 12 页实质内容、来源、数据及主题基调，只升级布局，输出新旧 PPTX、PDF、全页预览及差异说明。推荐方案能否被迅速找到、表格是否可投屏读懂、图表是否有解释、每页是否有焦点，由人工复核并记录，不捏造“设计提升百分比”。

### M1 验收门槛

- 拟上线的布局逐一有稀疏、常规、密集、长中文标题和边界材料样本。
- 可支持的所有对象进入几何模型，来源与稳定元素标识不丢失。
- 新版本保持原生文字/图表/表格；有图片的页面不等于把整页栅格化。
- 同份导出文件的 PDF/页图、页数、版本和下载一一对应。
- 自动检查不出现阻止交付的问题；视觉、语义和接收端编辑仍需人工验收。
- 保存旧协议测试，不能让既有 `slides.compose`、`slides.inspect` 和生成样本失效。

## 六、M2：原生数据表达、品牌和图文能力

### 数据表达优先级

1. 强化现有柱状/折线：横向条形、排序、长标签、重点系列、单位、分母、时间范围和来源区。
2. 在生成库和目标软件实测通过后增加堆积柱、百分比堆积与合适的环形图。组成是否互斥完整、百分比的分母和空值策略须明确。
3. 瀑布、漏斗、复杂组合图后置：先验证原生支持、数据工作簿及编辑结果；不能因为库可画形状，就称为原生可编辑图表。
4. 新增排序/差值/比例等计算必须有明确授权范围、字段类型、输入行、计算过程与舍入记录，不能从图表需求反推不存在的数据。

### 品牌系统

将现有三组固定主题升级为可复用品牌令牌：主色、强调色、背景、标题/正文/数字字体、网格、留白、表格与图表样式、页码和来源区。

- 首先支持人工确认的 Logo 与图片上传，先用受支持的安全栅格格式；复杂矢量须单独做安全解析，不直接执行上传 SVG。
- 校验像素、解码内存、文件类型和总资源预算；不允许模型随意给 URL 让服务器抓取。
- 字体必须有授权和渲染端支持，不能只在浏览器里看起来正常。
- 保存素材 owner、内容哈希、许可/来源、裁切参数与使用页。
- 没有图片时使用适当的原生图示，不捏造产品实拍、客户 Logo 或人物背书。

### 验收

- 每种新增图表有原生对象、嵌入数据、原始单元格、实际 PDF/页图和目标 Office 重开编辑的证据。
- 同一稿换品牌，事实与字段绑定不改变；无字体/无素材时明确提示，不静默替换。
- 图片、字体、预览、ZIP 和来源报告全部计入现有成果/存储预算。先测量资源消耗，再决定是否调整目前限额；不直接取消限额。

## 七、M3：有界修复、单页修改及持久工作区

### 先做安全可控的修改

先支持：修改标题/正文、重排顺序、选择兼容布局、更换已支持的图表表达、全局主题切换。自由拖拽、任意母版编辑和复杂动画不作为首批承诺。

- `slides.revise` 作为拟新增入口：输入基础版本、目标页/元素和受支持操作；不是当前已经存在的 API。
- 每次修改保存父版本、新版本、修改意图及影响范围；多端冲突拒绝覆盖，提供明确恢复选择。
- 单页修改保持其他页的内容、布局与数据绑定不变；以规范/布局哈希和页图检查验证，不要求整个 PPTX 二进制完全相同。
- 撤销/回退恢复真实历史版本，不是重新调用模型“猜回去”。
- 修改数据源、切换所有者或改变外部正文处理范围后，重新校验输入并按需重新授权。

### 有界质量修复

- 规则检查覆盖文字、图表、表格、图片及可明确计算的遮挡；图表内部标签需单独测量/解析，不能因记录了图表外框就宣称已检查内部。
- 自动修复只允许变更已批准的视觉布局；涉及语义修改、删除事实、调整数据或增加页数时，先征求确认。
- 建议至多两轮自动视觉布局修复，记录每轮差异；这是拟议上限，非当前已实现能力。仍失败则交付诊断或暂停，不无限调用模型。
- 视觉模型评审作为可选外部调用，说明发送的页图范围、权限和成本；不默认上传，不取代规则检查和人工签核。

### 界面与持久化

提供缩略图、真实渲染预览、内容/布局/来源面板、问题列表、版本与下载入口。复用既有 owner 隔离、任务关联、运行队列和产物下载；文稿和版本需要正式持久化设计，不把浏览器 localStorage 当作唯一事实源。

## 九、发布前的共同验收标准

1. **内容**：结论可定位，每页有实质信息；事实、分析、建议和待确认项清晰；缺证据不补造事实。
2. **数据**：展示值可重算/回溯，单位和统计范围清楚；没有隐式聚合、错分母或缓存公式冒充结果。
3. **视觉**：层次、对齐、留白、投屏可读性与整套节奏由规则检查和人工记录共同验证，不仅看封面。
4. **原生编辑**：真实文字、图表与表格可在指定目标软件中编辑；图片内文字不算可编辑文本。
5. **一致性**：文稿、编辑预览、下载 PPTX、实际 PDF、页图和质量报告关联同一版本。
6. **安全与资源**：无授权不发送材料/页图；未配置不假成功；跨 owner 不可访问；重试不静默重复计费；素材不突破配额。
7. **历史兼容**：原输入协议与既有案例继续可用，新能力不得破坏原技能路径。
8. **质量状态**：技术完成、待人工复核、人工确认分开。不能由模型或无关键问题的自动检查直接授予商业批准。

## 十、实施取舍与待确认项

### 推荐第一批范围

**M0 + M1**：真实自动规划验收、版本化布局底座、12 套建议布局和领导决策案例的新旧同内容对照。先证明“能自动写得清楚、能明显排得更好”，再做全量编辑器。

后续顺序：M2 数据与品牌 → M3 修订/工作区/有限修复。未来再讨论 PDF/OCR 扩展、任意旧 PPT 导入重建、动画和分布式调度。

### 不在本轮方案中承诺

一键生成任意商业定稿、咨询公司级效果保证、自动事实正确认证、任意旧稿无损编辑、所有 Office 全兼容、所有复杂图表原生可编辑、确定的工期/成本/提效比例。

### 启动实施前确认
