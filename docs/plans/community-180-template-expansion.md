## 制作与验收要求

1. **先建立制作清单**：180 个唯一 ID、题材、目标受众、设计方向、20–30 页内容目录、摄影/插画/媒体来源、交互清单、导出格式和验收状态。尚未完成的项目不能在产品中显示成已完成作品。
2. **独立设计**：每套有明确的信息架构与视觉语言；允许复用底层播放、存储、导航和导出工具，但不能只换颜色、标题和背景图。图片有内容意义，不硬塞每页，不冒充真实场所或客户案例。
3. **真实对应媒体**：
   - 原型：关联业务页面与完整本地演示流程。
   - 幻灯片：20–30 张真实幻灯片，编辑、演示和 PPTX 交付。
   - 文档：20–30 页实质内容、图表或表格，可编辑并诚实说明导出能力。
   - 图片：20–30 个独立构图画板，支持真实图片/可编辑图形交付。
   - HyperFrames：20–30 个内容页面组成的动效项目，有可运行的时间轴/动画；未集成第三方引擎时必须明确说明。
   - 视频：20–30 个内容页面，每页提供有意义的实际影片内容及对应编辑/播放操作，不用静态封面冒充视频。
   - 音频：20–30 个内容页面，真实可播放的音频与有意义的参数或编辑操作，不用波形图片冒充声音。
   - 实时产物：20–30 个相互关联、输入驱动真实计算或行为的工作页面。
   - WebGL：20–30 个有区别且能实际操作的三维内容页面，不用静态截图或同一模型换色凑数。
4. **可操作性**：可编辑自己的内容，本地保存、刷新恢复、独立复制；导航、按钮、播放、参数和下载必须实际工作。沿用既有已批准工作区的撤销/重做、命名版本等能力时必须真实接入，不放假按钮。
5. **业务边界**：本地演示不等于后端服务；未接入的支付、预订、发送、上传、云同步、市场行情或任意源码执行不能伪装成功。
6. **素材与性能**：保留来源和许可证；合理压缩、懒加载及按需加载；不要把大型源素材、缓存或测试截图塞入 Git。新增大型媒体先评估 GitHub 与会话产物限额，再采用仓库允许的资产存储方案。
7. **回归验收**：逐套检查内容页数量、核心流程、编辑保存、副本隔离、真实导出、坏数据和失败提示；检查手机/平板/桌面布局、中文字体与输出文件的实际视觉。不能仅靠构建成功或文件签名宣称商业质量。
8. **分批交付**：制作清单确定后按小批实现、视觉检查和自动化测试，记录每套完成状态；分批是执行方式，不减少 180 套的总范围。FORME、ATELIER、ROOTS、DAYLIGHT、TIDE、MORROW 各 24 页已实现并验收；实际新增 6/180，另 174 套仍须逐套设计和实现。
