> 后续状态：专家目录、确定性执行器、单技能规划/确认及任务内入口已陆续实现，最新状态见[剩余任务台账](remaining-work-ledger.md)与[任务内接入说明](task-skill-integration.md)。以下早期盘点中的相应条目不能直接当作当前全部未实现。

## 1. 本轮结论和范围

用户要求先暂停扩充页面，盘点并接通缺失功能。最初盘点后，已在 2026-10-15 接通同源 API、独立会话/基础账号、项目持久化、14 套模板服务器快照和 Studio 的 FFmpeg 转码。详见 [后台接入说明与验收](backend-connection-report.md)。这不是全部业务后台完成；未调用真实付费模型、支付或外部发送。

最新模板进度为 **6 / 180**：FORME、ATELIER、ROOTS、DAYLIGHT、TIDE、MORROW 各 24 页已实现并验收；另外 174 套未实现。社区共 19 套作品，用户已要求恢复扩展制作。此前浏览器测试证明的是其对应的前端/本地功能，不能作为生产业务已接通的证据。

### 状态定义

- **本地可用**：浏览器内实际计算、编辑、播放、保存或导出；不是后台完成状态。
- **已有基础，待接通**：已有前后端代码或接口适配器，但当前入口未形成已验证的在线服务闭环。
- **入口/演示**：目前为目录、提示、示例数据或模拟业务流程，没有对应实际服务。
- **待细查**：代码存在不等于已经可用，需后续启动服务并逐接口验证，不能直接判断全部未实现或全部完成。

### 最新接入状态

- `/api/health` 已返回真实 JSON；无会话的项目请求返回 401 JSON，不再是 HTML 假成功。
- Web 5173 与 API 8787 已同时运行，可用 `pnpm dev:full` 统一启动。
- 工作区状态可注册/登录/退出；19 套社区作品可显式服务器保存、冲突检查与跨浏览器恢复。
- FFmpeg 已安装，Studio 可以真实导出 MP4；其他机器需要配置对应运行时。
- AI 凭据、OAuth、真实订单/库存/支付/物流、任务执行系统等仍未完成，不计入已接通范围。

### 接入前的历史基线（以下问题已修复，不是当前状态）

1. 进程检查只看到 Web Vite 开发服务，未看到运行中的 local-daemon。
2. 请求接入前预览 `GET http://127.0.0.1:5173/api/projects` 返回 **HTTP 200 / text/html**，不是项目接口应返回的 JSON；不能将 HTTP 200 当作 API 成功。
3. `apps/web/vite.config.ts` 当时没有 API 反向代理配置。
4. `server/api/http-handler.ts`、SQLite 项目仓库、成员权限、聊天流、转码等代码存在；`server/local-daemon.ts` 也存在。不能据此说整个仓库只有前端，但当时它们没有因运行 Vite 自动接通。
5. 当前审计没有尝试外部 AI 服务、支付、OAuth 或生产发布，也没有检查或展示任何密钥内容。

## 6. 建议实施顺序

### P0：先让系统可以真实保存并执行

- **已做**：同源 API、JSON/HTML 判定、基础身份、项目持久化、模板快照/冲突恢复和 FFmpeg 接入。
- 复用仓库现有服务模块，完成身份/会话、数据库、对象/文件存储、任务状态、服务器权限和审计记录；不是全部从零重写。
- 打通“创建任务 → 执行 → 保存产物 → 再次打开”的完整链路。
- **已验证对应项目/模板范围**：重启持久化、身份隔离、失败不显示成功；对象存储、任务执行记录和生产审计尚未完成。

### P1：先完成一条平台任务线，再完成一条模板业务线

- 平台：输入与附件 → 模型/专家/技能 → 真实执行 → 产物编辑 → 保存/导出。
- 模板：以 FORME 为样板，商品后台 → 前台真实商品/SKU → 采购/报价 → 服务端订单 → 管理端处理。支付先使用可验证的测试环境；正式支付和外部发送另经确认。
- 两条线分别验收，避免把“任务对话能回复”当成“家具订单能履约”。

### P2：扩展真正的媒体能力与通用运营

- 视频渲染、音频编辑/混音、模型/纹理资产、文档解析等按用户实际使用场景接入。
- 定时任务、通知、连接器执行、协作、版本和发布共享通用基础设施。
- 功能底座验收后，继续新增剩余 174 套模板；复用底层能力，不复制假业务状态。

## 7. 后续每项功能的验收口径

1. 前端事件确实调用对应业务接口，接口执行的是该功能，不是返回固定成功。
2. 服务端校验输入和权限，持久化结果；不信任前端传来的总价、身份或成功状态。
3. 刷新、重启、换设备后在权限允许下仍能读到结果。
4. 外部业务以真实服务响应/回调为依据；未配置、失败、取消、超时均有对应状态。
5. 后台可检索和处理相同数据，前台和后台一致。
6. 导出内容与当前数据一致；只有在真实产物完成后才提供下载。
7. 对破坏性操作、付费、发送、发布与敏感资料访问设置必要的确认和权限。
