## 0. 总览：为什么这些必须由你提供

12 位专家共 40+ 个高级子任务。仓库现状分三类：

| 类别 | 状态 | 缺口来源 |
|---|---|---|
| 纯代码/规则可完成 | 我可以单独推进 | 无需你参与（详见第 5 节） |
| 需要真实业务素材才能验收 | 阻塞在"验收基准" | 你提供**真实样本 + 期望答案** |
| 需要外部账号 / 凭据 / 部署环境 | 阻塞在"通道" | 你提供**凭据与账号**（自建能力不存在） |

运行时目录 `shared/skillRuntime.ts` 中有 **5 个技能仍是 `status: "unavailable"`（未接入占位）**，它们正好是 4 组硬阻塞的根：

| 占位技能 | 对应子任务 | 缺什么 |
|---|---|---|
| `collaboration.sync` 外部日历与消息同步 | C1–C4 | OAuth 应用 + 可写沙箱账号 |
| `image.generate` 生成式图片与商品抠图 | M1 / M2 / M4 / I1–I4 | 图像模型端点或本地权重 + 许可 |
| `web.verify` 网页生成与浏览器验证 | W1–W3 | 能跑用户代码的隔离运行器 |
| `code.build` 隔离构建与全栈运行 | F1–F5 | 隔离运行器 + 部署目标 + 凭据 |
| `test.browser` 浏览器与接口验收 | T1–T4 | 隔离运行器 + 授权测试目标 |

> 仓库里**没有任何图像生成适配器**（只有 `@napi-rs/canvas` / `sharp` 等栅格处理），**没有任何邮件发送或日历同步通道**（`email-marketing.ts` 只产 HTML/EML 级文件，ICS 只是文件下载），**离线 ASR 只有英语 pocketsphinx**（`scripts/setup-asr.py` + `server/skills/asr-assets.json` 哈希校验，固定版本、仅 Linux x86_64 + Python 3.11）。这三件事无法靠写代码补出来，必须你给通道。
