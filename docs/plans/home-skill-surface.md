# 首页痛点对应的技能界面方案

## 目标与原则

技能界面要紧贴首页三种工作模式——**办公提效、设计制作、网页应用**——以及用户选择的具体痛点，而不是把一组互不相关的工具卡片摆成“技能商城”。

信息关系建议统一为：

> 工作模式 → 痛点类别 → 主责专家 → 可用执行技能 → 材料与授权 → 结果和人工复核

关键边界：

- **专家**负责判断、拆解与核验方法；**技能**是确实能执行的程序/服务；**任务模板**只是提示词或可复用说明。三者分开标记。
- 只有服务端 `runtimeSkills` 中真实注册、状态为 `ready` 的技能才显示“可执行”。`manualOnly` 必须单次授权；`unavailable` 不显示执行按钮。
- 当前 `frontend/workspace/skillCatalog.ts` 中大量条目只是本地任务预设，不会安装程序、启用 API 或自动调用服务。应显式标为“任务模板 / 模型辅助”，不要包装成已安装工具。
- 每张可执行技能卡显示支持格式、输入上限、输出、关键限制、数据去向、授权要求和人工复核点。不得由专家档案推导不存在的技能。

## 首页呈现方案

### 1. 延续现有三种模式

首页“办公提效 / 设计制作 / 网页应用”模式切换不变。选择模式后，仍使用现有痛点分类菜单和模板，不另加一排首页首屏卡片。

### 2. 在当前痛点模板附近提供“可用技能”入口

用户选中具体痛点类别后，在现有任务推荐附近展示最多 2–3 个**与该类目直接相关且当前可用**的技能入口：

- 有可执行技能：显示“可执行”及具体格式/限制，点击进入对应技能的真实参数与文件确认界面；不自动上传或执行。
- 需要人工授权的技能：显示“需单次授权”，点击后说明将发送给哪个已配置服务，再由用户主动确认。
- 只有提示词/模型辅助：显示“模型辅助 · 不调用文件工具”，操作是把任务说明填入对话框，不称为运行技能。
- 未接入能力：显示“尚未接入”，不显示运行按钮；可提供替代人工流程或说明。

首页选择类别只决定相关专家和技能候选，不意味着授权、文件已读取或后台任务已开始。技能实际执行继续在现有文件技能执行台内完成。

### 3. “技能”页按工作模式和痛点重组

建议主导航保留技能页，但页面入口改为三个模式分区，再以痛点过滤：

- 办公提效：文档整理、数据表格、会议纪要、周报总结、汇报PPT、邮件沟通、计划排期、调研分析、流程规范、协作跟进、其他问题。
- 设计制作：海报配图、产品展示、社媒内容、品牌物料、信息图表、电商物料、宣传长图、演示美化、视觉方案、图片优化。
- 网页应用：企业官网、活动页面、产品原型、数据看板、实用工具、作品展示、商品服务、表单收集、业务后台、内容站点。

每个过滤项下分别显示：可执行技能、模型辅助任务模板、尚未接入能力。默认优先展示有真实执行器的技能，并提供“只看可执行”筛选。

## 痛点—专家—技能映射

“技能候选”是按目标筛选，不代表该类目的所有任务都能由这些技能完成。

| 首页模式/痛点 | 主责专家 | 当前真实技能候选 | 能力提示 |
|---|---|---|---|
| 办公 / 文档整理 | 文档整理专家 `documents` | `document.format`、`document.structure`、`pdf.extract`、`pdf.ocr`、`pdf.ocr-batch`、`image.ocr`；`document.summarize` 需单次第三方模型授权 | DOCX/PDF 有格式、页数和结构限制；语义摘要必须核对来源。没有自动读取未上传文件。 |
| 办公 / 数据表格 | 数据分析专家 `data` | `table.analyze`、`table.calculate`、`table.join`、`table.join-multi`；图表可选 `infographic.compose` | 仅支持规定的 CSV/XLSX/ZIP 输入、字段、公式与行数限制；不能猜业务口径。 |
| 办公 / 会议纪要 | 会议纪要专家 `meeting` | 无中文或长会议 ASR；文字材料可使用对话模型，文档解析沿用 `document.format`；`audio.transcribe-en` 仅手动、短英语 WAV | 必须写明：只整理所提供的文字。英语短音频技能不等于中文/多语种会议转写。 |
| 办公 / 周报总结 | 周报总结专家 `weekly` | 当前没有专用周报自动采集技能；用户给出文字/文档后可用模型辅助，文档读取/导出沿用已有文档技能 | 不自动接入项目系统，不补造成果、进度、KPI 或负责人。 |
| 办公 / 汇报PPT | 汇报提案专家 `slides` | `slides.compose`（含结构化JSON原生对象）、`slides.inspect`、`pdf.extract`；文档读取可用相应 DOCX 技能 | 本机LibreOffice可产逐页渲染证据与主题令牌；若目标字体缺失会在摘要/报告中提示，相关文字可能替代或缺字；非PowerPoint像素级验收，不自动检测文字溢出/重叠，不等于AI改写或配图。 |
| 办公 / 邮件沟通 | 工作协作专家 `communication` | 无已接入邮箱发送技能；模型辅助起草 | 清楚标为“草稿”，不显示已发送。 |
| 办公 / 计划排期 | 工作协作专家 `communication` | `collaboration.schedule` | CSV 排期校验与无冲突时导出 ICS；不写入外部日历、不通知他人。 |
| 办公 / 调研分析 | 资料总结专家 `research-summary` | `document.summarize`（需单次授权）、PDF提取/OCR；表格数据可转 `data` 技能 | 未接入检索服务时不称“联网研究”；摘要需依据实际可读材料。 |
| 办公 / 流程规范 | 文档整理专家 `documents`（未来可拆流程专家） | `document.format` / `document.structure` 可做文档整理；没有专用流程挖掘/制度校验器 | 流程内容由模型辅助整理；不代表公司制度、审批权限已核验。 |
| 办公 / 协作跟进 | 工作协作专家 `communication`（未来可拆跟进专家） | `collaboration.schedule` 只校验 CSV 并导出 ICS；`collaboration.sync` 不可用 | 不发送邮件、不联系同事、不创建外部日历事件。 |
| 办公 / 其他问题 | 问题分诊专家 `triage` | 先确定类别，再只列真实可用的技能；不确定则不推荐执行器 | 分诊不是通用执行技能；技能缺失时坦白并给人工替代步骤。 |
| 设计 / 品牌物料、视觉方案 | 品牌视觉专家 `brand` | `brand.assets`、`brand.system` | 按受限输入生成色板/变量/模板化品牌草案；不是商标检索或完整品牌创意。 |
| 设计 / 海报、宣传长图、社媒物料 | 营销物料专家 `visual` | `image.marketing`、`image.layout` | 需要用户实际提供图片与文案；固定/分层排版导出，不是生成式生图或自动发布。 |
| 设计 / 产品展示、电商物料 | 产品展示专家 `product-visual` | `image.product`；其他图片布局可按条件使用 `image.layout` | 可做限定的尺寸适配和排版；抠图、修复、AI重绘 `image.generate` 未接入。 |
| 设计 / 信息图表 | 信息可视化专家 `infographics` | `infographic.compose`；表格来源可先用 `table.analyze` | 需明确单位、来源、口径和图表目的；不推断业务含义。 |
| 设计 / 演示美化 | 汇报提案专家 `slides` 或视觉专家 `visual`，按目标选一位主责 | `slides.compose` 可按显式JSON token生成原生对象；`slides.inspect` 可提取PPTX结构/主题并本机渲染 | 不把结构统计和LibreOffice预览说成模板导入、自动视觉验收或Microsoft PowerPoint验收；须人工逐页检查。 |
| 设计 / 视觉方向、图片优化 | 视觉专家 `visual` | `image.layout` 可做受限的显式图层排版；生成式图像 `image.generate` 不可用 | 其余是模型辅助的设计建议，不冒称图像已处理。 |
| 网页应用 / 全部网页类目 | 网页交互专家 `web-design`、开发专家 `developer` 或测试验收专家 `qa`，按主要目标设一位主责 | `web.audit`（HTML静态检查）、`code.inspect`（JS语法/有限风险检查）；`web.verify`、`code.build`、`test.browser` 当前不可用 | 静态检查不等于浏览器交互、接口、运行、安全或无障碍验收通过。网页生成/预览与技能执行分开标注。 |

## 技能界面卡片字段

每张卡片统一包含：

1. 名称与类别：对应的首页痛点及主责专家。
2. 状态徽标：`可执行`、`需单次授权`、`模型辅助`、`尚未接入`。
3. 输入/输出：接受格式、文件大小/页数/行数上限、真实交付文件类型。
4. 能力限制：拒绝条件、未支持语义、精度/分页/渲染限制。
5. 数据与权限：本地处理还是发给已配置第三方模型；如需外发，执行前单次授权。
6. 人工复核：列明需检查的来源、数字、文字、版面或运行结果。
7. 操作：真实技能才有“选择文件并配置”；模型辅助任务只能“填入任务说明”；未接入项只有“查看限制/替代方案”。

## 研发阶段

### P0：可执行能力与界面分层

- 以服务端技能注册表为唯一执行状态来源；整理技能 ID、对应痛点、主责专家、协作白名单和状态。
- 将 `skillCatalog` 内提示词预设与 `runtimeSkills` 的真实执行器分离显示。移除“已安装/执行”会让人误解为安装外部程序的文案。
- 先覆盖当前实际 ready 技能和 manualOnly 授权流程；未接入项保留能力说明但关闭运行操作。

### P1：首页按痛点展示

- 从当前模式和所选具体类别读取技能映射，在模板区提供少量相关技能入口。
- “全部分类”只用于浏览；选定具体类目后才展示对应技能。
- 手动选择专家后，只过滤技能候选，不绕过执行时服务端专家绑定检查。

### P2：完整技能目录

- 将技能页重组为办公、设计、网页三个模式及痛点筛选，添加只看可执行、文件类型和授权状态过滤。
- 每项技能详情复用统一能力卡字段；运行、失败、取消、结果下载、复核状态统一展示。
- 对高优先级未接入能力（中文/多语种长会议ASR、生成式图片、网页浏览器验证等）先定义输入、数据去向、验收集和权限，再决定接入；没有凭据/模型/许可时保持关闭。

## 验收

- 首页每个已列痛点只展示允许专家和实际可执行技能；用例验证不会把模板推荐误当成后台执行。
- `ready` 才有执行操作；`manualOnly` 未单次授权不能运行；`unavailable` 不可触发调用。
- 用户确认前，文件未上传、外部服务未调用；仅本地策略不会发起云端技能请求。
- 技能名称、可接收格式、输出文件、实际执行和状态报告一致；失败不能伪报成功。
- UI 在宽屏和手机显示模式/痛点/状态时无横向溢出，键盘可访问，授权与复核说明可读。

## 当前状态

本方案是设计与落地顺序，不代表所有技能已完成。应用已经有若干受限的真实 Office/设计/静态代码技能；许多市场条目仍只是本地任务说明，部分执行器明确标为 unavailable。ASR中文/多语种长会议、图片生成/抠图、浏览器运行验证、邮箱和外部日历同步等未接入能力不得在界面中开放为可执行项。
