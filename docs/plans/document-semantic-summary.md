# 文档语义摘要：第一阶段实现与剩余验收

日期：2026-10-16。此文件记录第1方向的一个真实实现切片；**不将文档理解与还原方向标记为完成**。

## 已实现切片：需明确授权的云端语义摘要

- 新增手动技能 `document.summarize`，输入仅限 UTF-8 TXT/Markdown 或 DOCX 主文档文字段落；当前限制沿用2MB、60000字符、1000个非空段落边界。DOCX表格中的文字可能在提取时展平，不能还原表格关系；图像、OCR、页眉页脚、版式和页面位置不进入摘要上下文。
- 使用服务器端既有 OpenAI-compatible AI 设置（`AI_API_KEY`/`OPENAI_API_KEY`，可选 `AI_BASE_URL`、`AI_MODEL`），使用已认证的运行所有者发起真实服务端请求。不在浏览器暴露密钥；若未配置密钥，技能在目录中标为不可用，不产生模板/伪摘要。
- 摘要执行前需要两个独立操作：允许上传至应用后台；再从摘要专属选项中单次明确同意将完整提取正文发送至服务端配置的第三方模型。目录和确认文案说明第三方处理及其留存政策归服务商决定。
- 按来源段落标注文本并分块；要求摘要引用段落标签。无引用、引用不存在或整合引用越界时失败，不交付部分成果。输出 Markdown、输入哈希/模型/外发声明报告及常规执行回执。引用标签仅可帮助人工回查，不能证明摘要语义正确。
- OpenAI-compatible 请求禁止自动跟随重定向，避免请求凭证及正文被重定向转发。

## 测试证据与验收状态

`server/skills/document-summary.test.cjs` 的4项测试使用 mock transport，验证：缺少授权/所有者不发请求；获得双重授权后正文进入预期模型请求且产物记录第三方处理；模型伪造段落编号时失败且无部分结果；服务端模型未配置时技能不可用且不伪造结果。TypeScript 和相关服务/规划器测试通过。

**没有真实服务商凭据，因此尚未执行真实云模型调用、费用/延迟/中文与长文摘要质量评估或浏览器端完整工作流。** 不能把 mock 测试描述成真实服务商验收；部署启用前还需核对提供商端点、隐私政策、数据保留和用户告知。

## 本轮后续：更宽批次OCR与DOCX版式属性保留

`pdf.ocr-batch` 已扩大为 2–4 个 PDF、合计最多 8 页（原为2–3个文件/6页），保持2MB ZIP、6MB展开量、每个PDF≤2MB和≤8MB产物上限；该技能的Worker执行时限提高到120秒。仍是单任务、整批原子交付；不支持无界批次、断点续传或后台长任务。真实本地OCR Worker 对4个PDF共8页完成处理，每页均有识别文字及哈希/PNG证据；结果与输入哈希见[可复验产物](../verification/pdf-batch-expansion-2026-10-16/results.json)。输入为合成测试材料，不是业务文档准确率评估。

`document.structure` 现在额外保留可验证的直接段落左缩进、首行缩进、段前/段后距、行距/行高、keep-with-next，以及表格网格列宽、单元格背景色和垂直对齐，并输出相应结构字段及HTML样式。专项DOCX结构测试12/12通过。
