# 对话分类入口的痛点—专家对应方案

## 需求范围

本方案针对对话输入框上方的办公分类入口：当前直接显示“文档整理、数据表格、会议纪要、周报总结、汇报PPT”，并由“全部分类”打开其他办公类目。点击类别是选定工作痛点/模板，不是新增首页首屏卡片，也不是新增任务进度面板。

目标：每个具体痛点类别都有清楚、唯一的主责专家；复杂任务最多建议两位可选协作专家；“全部分类”只负责展开分类，不作为专家，也不代表万能能力。

## 分类映射

| 对话入口类别 | 主责专家 | 可选协作专家（仅在确有需要时） | 责任边界 |
|---|---|---|---|
| 文档整理 | 文档整理专家 `documents` | 资料总结 `research-summary`（材料综合）；数据分析 `data`（文档中的数字核对） | 结构、格式、校对、版本差异；不自动读取未上传/无法解析的文件 |
| 数据表格 | 数据分析专家 `data` | 信息可视化 `infographics`（需要图表）；汇报提案 `slides`（明确要做汇报） | 字段、口径、清洗、统计与追溯；不推断未提供的业务口径 |
| 会议纪要 | 会议纪要专家 `meeting` | 工作协作 `communication`（后续跟进）；数据分析 `data`（会议指标核验） | 依据文字记录整理讨论、决议、争议和待办；不冒称音频转写 |
| 周报总结 | 周报总结专家 `weekly` | 数据分析 `data`（指标）；汇报提案 `slides`（转为汇报） | 依据真实记录归纳成果、风险、计划；不编造业绩或外部项目状态 |
| 汇报PPT | 汇报提案专家 `slides` | 数据分析 `data`、文档整理 `documents` 或信息可视化 `infographics`，按材料需要选择 | 负责听众目标、故事线和逐页内容；PPT文件生成仅限实际已接通的技能 |
| 邮件沟通（全部分类中） | 工作协作专家 `communication` | 文档整理 `documents`（长材料）；问题分诊 `triage`（目标不清） | 起草与措辞建议；不声称已发送邮件或联系对方 |
| 计划排期（全部分类中） | **建议新增：计划排期专家 `planning`** | 工作协作 `communication`（跨团队依赖）；数据分析 `data`（有排期数据时） | 根据明确资源、期限和依赖安排计划；不擅自写入日历或项目系统 |
| 调研分析（全部分类中） | 资料总结专家 `research-summary` | 数据分析 `data`（量化分析）；汇报提案 `slides`（需要报告呈现） | 依据已提供材料整理证据、差异、限制；不虚构联网检索或来源 |
| 流程规范（全部分类中） | **建议新增：流程规范专家 `process`** | 文档整理 `documents`（手册成稿）；问题分诊 `triage`（职责/规则不清） | 梳理输入、步骤、角色、异常与验收；不替组织编造制度或审批权限 |
| 协作跟进（全部分类中） | **建议新增：协作跟进专家 `follow-up`** | 会议纪要 `meeting`（来源于会议行动项）；计划排期 `planning`（有依赖与时间计划） | 整理责任、阻塞、沟通草稿和下一步；不声称已催办、排期或获得回复 |
| 其他问题（全部分类中） | 问题分诊专家 `triage` | 只推荐与澄清后的目标直接相关的 0–2 位专家 | 先界定问题、材料和验收结果；不是执行专家，不承诺万能解决 |

**分类隔离建议：**专家主页的 `homeCategories` 应尽量表示专属主责类目。当前“文档整理专家”兼列会议纪要、周报总结、流程规范，会与新增的专门角色产生重复认领；在正式路由前，应将会议、周报从其主责分类中移出。文档专家仍可作为上述任务的可选协作。

## “全部分类”的交互规则

1. “全部分类”是分类浏览菜单，不写入任务，也不参与专家匹配。
2. 用户从菜单选择具体类目后，保存稳定的 `categoryId`（例如 `office-meetings`）及当前子类目/任务组；不能只依赖自由文本中是否恰好出现“会议”“周报”等关键词。
3. 用户选择模板后仍可编辑提示词；主责由所选痛点提供强默认值。若实际目标明显属于另一类，匹配器应先询问是否切换主责，而不是默默换人。
4. 用户没有选具体类目、选“其他问题”，或所选类别与目标冲突且无法判断时，交由分诊专家澄清；简单问候或轻微改写仍可直接处理。

## 路由和展示方案

- 建立一个共享 `categoryId -> primaryExpertId + allowedCollaboratorIds` 映射，作为目录、首页匹配、专家详情和测试的单一数据源。
- 将 `categoryId` 从分类菜单/任务模板传入现有专家匹配请求；服务端只接收目录内候选 ID，并把类别作为强路由信号。模型仍须基于实际目标、材料和交付物判断，不以关键词单独决定。
- 本地/无模型/仅本地模式也使用同一映射，确保离线时所选类别仍能匹配对应主责；结果必须标注为规则建议，不伪装成模型判断。
- 匹配面板固定展示一位“主责专家”，协作专家可为空；只有存在清晰的非重复补充职责时才显示协作。用户可手动锁定/切换主责。
- 专家职责档案不授予技能权限。文件技能候选仍由真实的技能绑定和执行权限决定；未接入的ASR、邮箱、日历、批量读取等能力必须明示未接入。

## 分阶段实施

### P0：路由契约与映射（下一步）

- 给全部办公分类建立稳定类别 ID、唯一主责 ID、可协作白名单及能力边界。
- 将现有专家的重叠类目收敛，新增计划排期、流程规范、协作跟进三个职责档案；这些档案只提供工作规范，不声称新增工具。
- 明确 `全部分类` 不参与路由，未分类任务进入分诊。

### P1：接入现有对话分类入口

- 分类菜单选中具体类别时，类别 ID 随任务模板传入输入框/匹配请求/新建任务记录。
- 自动匹配、手动切换、仅本地建议均共用映射；跨类别请求只允许一位主责并可选协作。
- 在现有专家匹配面板显示“类别 → 主责 → 可选协作”，不新增首页卡片，不改造成新的任务状态页面。

### P2：验证与能力开放

- 测试覆盖每个类别的默认主责、规则路由、模型路由候选约束、跨类澄清、协作去重和手动锁定。
- 验证“全部分类”本身不会被路由成专家；只有用户选定其下具体类目才使用类别映射。
- 技能绑定逐项核对；中文/多语种/长会议转写继续保持未接入，直至完成服务授权或用户提供模型和许可并验收。

## 验收标准

- 所有办公痛点类别都有且仅有一个默认主责专家；每个专家均有职责、输入、交付物、检查项和真实能力边界。
- 在所选类别下输入典型任务，无模型时仍能得到正确标注的规则主责建议；模型在线时返回的 ID 必须在允许候选内。
- 需要协作时最多两位、无重复且职责互补；简单任务不强行加协作。
- “全部分类”只展开目录；未选择具体类别的未知问题进入分诊。
- 专家档案不改变技能白名单、权限、ASR状态或外部操作授权。

## 当前状态说明

此前已在工作区增加会议纪要、周报总结、资料总结、问题分诊等专家档案，并增加“其他问题”办公类别及可选协作字段；但所选对话分类尚未作为稳定类别 ID 显式传入匹配请求。本方案将后续实现限定在现有对话分类入口及其路由，不要求新增首页痛点卡片或任务进度面板。
