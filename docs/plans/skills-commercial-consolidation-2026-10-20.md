# 技能界面精简与商业级质量升级方案

日期：2026-10-20  
状态：待用户确认；本轮只提供方案，不调整技能界面、不删除执行器、不接入付费服务。  
目标：用户看到少量完整能力，而不是大量底层工具；以真实、可编辑、可核验的工作成果作为交付标准。

## 一、建议结论

**主界面从目前源码登记的 49 项细分技能，收敛为 8 个核心技能产品。** 49 项是当前运行技能契约的静态登记数量，不代表本次环境或正式服务器全部可用、全部已商业验收。实际状态仍由服务端依赖和配置决定。

不删除既有底层能力、不清空运行记录。把提取、OCR、公式计算、排版、压缩、测试等作为核心技能的内部工序或自然语言功能选项，不再各占一张主卡片。也不把所有技能强塞成一个“万能助手”。

“商业级甚至更好”应拆为可验证的目标：内容可信、视觉专业、关键交互完整、产物真实可编辑、失败可恢复、过程与费用透明、隐私和许可可追踪。只能在具体任务及同条件比较中证明优势，不能在未比较、未验收时声称全面超过商业产品。

### 01 专业演示与汇报

- 先确认受众、用途、时长、材料和要决策的问题；信息已提供的不重复询问。
- 先给逐页内容和证据组织，再完成版式、图表、讲稿；不是把段落机械分成幻灯片。
- 采用按内容选择的封面、指标、对比、流程、风险、决策等版式，避免整套同一种卡片。
- 原生文本、表格和图表能编辑；不把全页图片冒充可编辑 PPT。
- 修改后重新渲染并逐页检查。若不能生成修改版 PDF，明确阻断该交付，不复用旧 PDF 冒充新版。
- 需升级：在既有 AI 规划、来源/单元格绑定、原生生成及逐页渲染基础上，提高叙事和版式质量，补齐专用编辑/会话修订/版本对比，增强溢出与遮挡检测和有限修复，完成目标 PowerPoint/WPS 兼容复核。自动配图供应商仍待选定，不擅自启用付费生图。

### 02 专业文档与资料处理

- 入口先选“制作正式文档 / 整理原文 / 摘要与提取”，不能未经确认改写合同、报告或原文事实。
- 正式文档具备语义标题、原生表格、页眉页脚、页码、必要导航与来源；目录、批注、图片和复杂格式须声明支持范围。
- 提取/摘要保留可定位来源；OCR 对金额、日期、姓名、编号等关键字段标记复核，不把识别置信度称为准确率。
- 逐页真实渲染检查；结构解析通过不能替代分页和视觉验收。
- 需升级：复用已接入执行台的 `document.create` 正式成稿、同源 DOCX/PDF 渲染及有限修复，扩展文种与复杂材料处理，补齐持续编辑、版本保留、跨次修改后重渲染，以及目标客户端验收。中文长会议转写不作为首发承诺；现有短英语 WAV 模块作为受限输入附属能力保留。

### 03 表格分析与业务报告

- 明确字段、主键、单位、期间、币种、去重与缺失值规则；不能默认猜测。
- 将清洗、关联、计算、报告作为可选任务配方；先预览影响，再执行破坏性转换。
- 保留原始文件及逐行来源；可追踪关联前后行数、异常、未匹配和公式结果。
- 图表解释与计算分离：计算有确定规则，业务结论必须有材料支持；不从相关性编造因果。
- 需补齐：字段映射界面、预览/确认、更多复杂工作簿兼容、保存计算规则。现有公式白名单与纯值输出不得包装成完整 Excel 保真编辑。

### 04 品牌与视觉系统

- 输入真实品牌定位、受众、使用渠道、已有资产及权利约束；缺失时先给方向，不编造品牌历史或市场背书。
- 方案形成完整系统，而不只是提取几个颜色：标志使用、字号层级、间距、图像方向、组件及应用样例。
- SVG 保持真正矢量结构，设计令牌可复用；与已有标志相似、字体许可和商标状态明确待复核。
- 需补齐：方向选择与人工审阅闭环、系列应用一致性、复杂标志质量。现有规则生成器不能直接称完整品牌创意服务。

### 05 营销与商品视觉

- 先明确投放渠道、尺寸、商品事实、文案、CTA、必填声明和素材许可。
- 一次任务产出同一视觉系统的主图及尺寸适配；不同尺寸要重排，不只是拉伸裁切。
- 标题、卖点、商品图和 CTA 可分别修改；保持原图、图层/布局参数、生成参数及版本。
- 质检包含中文缺字、长文案、裁切、安全区、对比度、多尺寸一致性；商品规格、外观不能被 AI 擅自改造。
- 需补齐：用户友好的可编辑项目、重排策略、质量检查；生成/抠图/修复通道按真实供应商能力分别验证，不能用缩放代替抠图或宣称所有兼容端点均支持透明背景。

### 06 网页与交互原型

- 输入页面目标、用户路径、内容、品牌、必要状态和数据接口；缺真实服务时保留演示标签。
- 交付不只有首页，还包括范围内的加载、空、错误、校验、成功和移动端状态。
- HTML/CSS/脚本检查、真实浏览器交互、接口测试和安全审查分别报告，不互相替代。
- 源码能下载、预览能打开、刷新后状态有明确规则；不能把静态展示声称为完整全栈应用。
- 需补齐：可修改项目、受控运行环境、端到端编排。任意不可信代码执行必须有真正隔离及资源/网络约束，现有受限本机进程不满足此发布条件。部署需单独确认。

### 07 项目方案与执行计划

- 将目标、范围、不做项、角色、依赖、交付关卡、风险及验收关联起来。
- 按情景提供“产品需求 / 项目计划 / 入职安排 / OKR / 事故清单”等内部模板，不为每个文稿生成器再建独立主卡片。
- 不补造负责人、日期、预算或进度；未知项进入待确认清单。
- 计划导出与真实通知/日历写入是两回事。外发必须确认具体对象、内容、次数和费用边界。
- 需补齐：方案正文质量、表格/日历/正文一致性、依赖调整与版本对比。事故清单只用于准备与记录，不替代自动生产处置。

### 08 设计与交付质量检查

- 先说明检查对象与范围：Office、页面、图片、代码、接口；不支持的对象不能只上传后返回通用建议。
- 每个问题要有文件/页码/元素定位、实际现象、严重度、依据和可执行修法。
- 将“发现问题 / 建议修改 / 已应用修改 / 复测通过 / 未验证”分开。
- 自动可修项可生成副本，用户确认后再应用；保留原始文件和差异，不静默覆盖。
- 需补齐：跨产物检查器、证据定位、修复后重测；不可声称测试通过等于安全、法律、无障碍或商业认证。

## 四、其余能力怎么处理

1. **底层工序合并**：OCR、提取、压缩、格式适配、语法检查等留在后台，由确定配方调用；提供技术详情，但不再占主界面位置。
2. **行业小工具变成场景**：财务报告、OKR、入职计划、FAQ、事故清单等进入对应核心技能的场景选项，保留原始能力边界。
3. **邮件营销归入项目内容交付场景**：`email.marketing` 仍只生成邮件文件；真实邮箱发送依赖协作通道单独确认，不能“生成即发送”。
4. **外部依赖作为条件模块**：图像生成、数据连接、邮件/日历写入等显示真实配置/授权状态，不能因为主技能能运行就默认全链路可用。
5. **维护/高风险能力不作为普通用户主入口**：`code.build` 等按信任与隔离条件限制；保留管理员诊断，未满足发布条件时不得以隐藏警告的方式提供服务。
6. **旧 ID 与运行记录兼容**：运行历史保留旧技能 ID、版本和凭据记录；收藏映射到对应核心入口并说明迁移，不抹掉原有用户记录。原接口是否弃用另行定义版本与迁移期。
7. **外部技能包不是上架数量**：之前接入的资源/定义作为内部方法库，逐项保留原许可与阻断条件；不能因为聚合进核心技能就绕过许可。

## 五、界面方案

### 主页面

- 顶部：一个任务输入框，提示“你想交付什么？”，可添加实际材料。
- 中部：8 张核心技能卡，按办公、设计、网页/项目分区；不再显示底层技能总数作为卖点。
- 每卡仅显示：成果名称、典型用途、真实交付、示例预览、当前可用范围，以及“开始制作”。
- 下部：最近使用、已保存任务、我的成果。暂未通过质量门槛的技能不进入可制作区；8 是目标目录，不要求一次全部上架。
- 移除普通用户的“添加技能”入口，替换为“反馈需求”；后台开发注册机制保留在维护侧，不让用户误以为点击就安装了执行能力。

### 单项工作台

固定五步：**确认目标 → 材料与范围 → 处理/制作 → 预览与修改 → 检查与交付**。

- 普通用户用自然语言和字段表单；JSON/底层技能 ID 放到可选技术详情，不作为主要使用门槛。
- 执行前显示输入范围、输出、外发对象、预计/上限费用及授权；不能可靠估算时说明计费规则，不编造价格。
- 进度来自真实步骤和事件，不播放虚假百分比；失败指向具体环节。
- 结果区提供当前版本、原始版本、差异、质量状态、下载与重新编辑。
- “运行完成”不等于“交付通过”：质量阻断时显示需要修复/待复核，不能以成功徽标掩盖缺字、丢内容或失败导出。

## 六、每个技能都必须过的发布门槛

以下是建议的本项目内部发布条件，不是行业认证，也不是本轮已通过的结果。

### 硬阻断：不能用评分抵消

- 丢失或篡改关键内容、虚构事实/来源，或关键金额与计算不一致。
- 原生可编辑承诺不成立、导出打不开、预览与交付版本不一致。
- 明显缺字、溢出、遮挡；关键操作无法完成或错误被当成功。
- 未授权外发、跨用户读取、密钥泄露、重复支付/发送、不可控代码执行。
- 素材、字体、代码依赖许可不明确且无可用替代。
- 必需依赖未配置或只做了模拟测试，却宣称真实外部服务通过。

### 必须有证据的检查

1. 内容：与输入逐项对应，有来源位置、字段含义、统计范围和公式；未知项不补造。
2. 视觉：适合具体用途的版式与层级；全页/全画板检查，中文、长文本及不同尺寸专项验证。
3. 编辑：修改真实作用于预览与最终导出；副本、撤销/恢复及版本边界明确。
4. 执行：正常、缺材料、无效输入、超限、中断、超时、第三方失败等场景分别测试。
5. 交付：用实际接收工具打开，必要时重算或重渲染；Office 分别做 Word 与 PPT 验收，不互相替代。
6. 安全与权利：用户隔离、输入校验、权限、删除/保留策略、成本限制、第三方授权及素材许可。
7. 运维：运行 ID、版本、输入/输出哈希、真实日志、失败原因、幂等与重试边界；回滚不能破坏旧任务。

### 如何验证“比普通商业产品更好”

每个核心技能选定具体竞品或人工工作流作比较，记录版本、材料、任务、价格档位与配置。比较：交付可用性、人工修改耗时、内容遗漏/错误、编辑便利、视觉偏好、总费用和失败可恢复性。评审尽量匿名、同材料同任务；人工评审、主观偏好与自动指标分别记录。

先提出目标，再采样和评审；没有结果不能写提升百分比。没有指定竞品时先以现有 DesignBuddy 结果为基线，不凭空声称全面领先。
