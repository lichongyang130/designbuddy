# 插件在首页直接运行：方案与已落地实现

> 结论先说：**插件能在首页跑，而且这次已经把入口打通了。**
> 你原来的 480 个插件是"能力规格"（声明），真正能执行的是 30+ 个 runtime skill；
> 本次改动把"已启用的插件包"搬到首页输入框正下方，点一下就把技能装进 composer，发出去走真实执行器。

---

## 1. 现状盘点（改动前）

| 层 | 位置 | 能不能执行 | 首页原来用没用 |
|---|---|---|---|
| A. 480 项目录 `plugins/_official/catalog.json` | 前端收藏（localStorage `assets[type=plugins]`）+ `/plugins` 详情页 | ❌ 只是能力声明 | ❌ |
| B. 4 个真实 Bundle `server/plugins/bundles.json` | 服务端 `data/plugins.sqlite` 真安装/停用/卸载 | ✅ 绑定 4 个已注册技能 | ❌ |
| C. 30+ Runtime Skill `shared/skillRuntime.ts` + `server/skills/*` | `createProject()` → 技能工作流 → 真实产出文件 | ✅ | ✅（但只能靠"附件菜单"选，路径深） |

问题不是性能，是**断层**：用户在 `/plugins` 装了包，回到首页看不到，只能重新去附件菜单里翻技能。

---

## 2. 本次已实现（P0 + 部分 P1）

### 2.1 首页新增「我的插件」轨道

- 新组件 `apps/web/src/components/HomePluginsRail.tsx`，位置：composer 卡片正下方、`HomeDiscovery` 之上。
- 数据来源：`GET /api/plugins?scope=home`（新接口，只返回**已启用**的包）。
- 内容优先级：已启用 Bundle → 本地收藏的目录插件 → 无数据时展示 6 个精选（并提示去挑选）。
- 交互：点击 = `setSelectedSkill(首个可跑的技能名)` + 把示例需求填进输入框 + 聚焦 + 顶部提示"仅填入，不会自动安装或授权"。
- 空态、离线态、停用后的缓存失效都已处理。

### 2.2 输入框下的「技能要求条」

- 新组件 `apps/web/src/components/HomeSkillHint.tsx`，替换原来那行只有名字的胶囊。
- 显示：技能名 / 接受的文件类型 / **还需要你提供什么**（`requires`）/ **会用到哪些权限**（`permissions`）/ 不可用原因。
- 当技能需要文件而你没上传时，直接给「选择文件」按钮（复用现有 `fileInputRef`）。
- 文案对齐服务端真实声明，不承诺没有的能力。

### 2.3 后端轻量接口 `GET /api/plugins?scope=home`

`server/api/plugin-registry.ts` 新增 `home(ownerId)`：

```json
{
  "apiVersion": "1.0",
  "bundles": [{
    "id": "bundle-docs-data",
    "name": "文档与数据基础包",
    "description": "…",
    "enabled": true,
    "readySkills": 4,
    "blockedSkills": 0,
    "requires": [],
    "skills": [{
      "id": "table.analyze",
      "name": "表格清洗与统计",
      "status": "ready",
      "accepts": [".csv", ".xlsx"],
      "requires": [],
      "permissions": ["local.read", "local.write"]
    }]
  }],
  "totals": { "enabled": 1, "readySkills": 4, "blockedSkills": 0 }
}
```

要点：
- **只返回已启用**的包，停用的不会出现在首页（`disabled` = 首页消失，技能目录不受影响，这是原有语义）。
- 每个技能带 `status`，配置缺失的技能（如 `document.summarize` 无 API Key、`image.generate` 无图像通道）标 `unavailable`，首页直接显示"待配置"，不会假成功。
- 未登录/无包时响应体仅 **90 字节**。
- 写操作仍然全部走 `sameOrigin()` 校验，跨站 403；这个接口没有任何写能力。

### 2.4 前端 API 与缓存

`frontend/workspace/api/plugins.ts`：
- `fetchHomePlugins()`：首页专用，失败时静默降级。
- `invalidateHomeRailCache()`：安装/停用/卸载成功后清除首页轨道缓存，避免"刚停用首页还显示"。
- 轨道本身 `sessionStorage` 缓存 60s，先渲染缓存再后台刷新（stale-while-revalidate）。

### 2.5 按需加载

- `/plugins` 路由改为 `React.lazy` + `Suspense`（原来是顶层静态 import），拆出 `PluginsPage-*.js 20.8 kB` + `PluginsPage-*.css 22.2 kB`。
- 首页轨道不静态引用 480 项目录：需要时才 `import()`，避免首屏拉 188 KB JSON。

## 3. 性能与体积（实测）

| 指标 | 改动前 | 改动后 |
|---|---|---|
| 首页额外请求 | 0 | 1 个（`scope=home`，1.0 KB；无包时 90 B） |
| 首页首屏 JS 主包 | 3 426 kB | 3 399 kB（−27.7 kB，PluginsPage 移出） |
| `/plugins` 首屏 | 跟随主包 | 单独 20.8 kB JS + 22.2 kB CSS 按需 |
| 480 项目录 | 随主包加载 | 首页不加载（路由内才需要） |
| 轨道渲染 DOM | — | ≤ 11 个按钮，横向滚动，不虚拟化也够 |
| 二次进入首页 | — | 0 请求（60s 会话缓存） |

> 说明：`DesignLibrary` 目前仍静态引用 `catalog.json`，所以 188 KB 目录暂时还留在主包里。把 `DesignLibrary` 一并改懒加载可以再省这一块，属于 P1 的收尾项，不是本次风险点。

## 4. 状态流（已实现）

```
/plugins 安装/停用 Bundle
        │  POST /api/plugins/install | /:id/status
        ▼
data/plugins.sqlite (installed_plugins)
        │
        ├──► /plugins 页面：全量 GET /api/plugins（展示 4 个包 + 日志）
        │
        └──► 首页：GET /api/plugins?scope=home （只读已启用）
                     │  sessionStorage 60s 缓存 + 后台刷新
                     ▼
             HomePluginsRail  →  点击
                     │  setSelectedSkill(技能名) + 填示例需求 + 聚焦
                     ▼
             HomeSkillHint  →  还缺什么（文件/授权/凭据）
                     │  点"发送"
                     ▼
             createProject() → 技能工作流（onStartFileTask / workflow="skills"）
                     │
                     ▼
             真实产出：DOCX / XLSX / SVG / PNG / HTML + 处理记录
```

## 5. 权限与安全

- 首页轨道**只做填入**，不安装、不授予任何权限；文案明确写了这一点。
- 技能权限仍由服务端 `skillPermissions()` 决定；`external.*`（第三方 AI / 图像 / 日历 / 邮件）执行前需要单次显式授权，首页只是**提前告诉你**会外发什么。
- `scope=home` 是只读接口；写接口保持 `sameOrigin()` 校验，测试里有跨站 403 断言。
- 不可用技能（缺凭据/缺环境）在首页就标灰，执行时服务端仍会拒绝，不存在"前端说能跑"的假象。

手工路径：
1. 打开 `/plugins`，安装「文档与数据基础包」。
2. 回首页，composer 下方出现「我的插件 · 1 个包 · 4 个技能可跑」。
3. 点该胶囊 → 输入框出现示例需求、下方显示"接受 .csv / .xlsx + 会用到读写权限"。
4. 不上传文件直接发送 → 提示需要文件；上传 CSV 后发送 → 进入任务页，由真实执行器产出 XLSX/报告。
5. 在 `/plugins` 停用该包 → 回首页轨道消失（缓存已失效）。

## 8. 回滚

本次改动是纯增量，无数据库迁移：
- 前端：删掉 `App.tsx` 里的 `<HomePluginsRail />` 与 `<HomeSkillHint />` 两处引用即可恢复原样。
- 后端：`?scope=home` 分支独立，其他路径行为未变；直接回退 `server/api/plugin-registry.ts` 即可。
- 样式独立在 `apps/web/src/home-plugins.css`，删除不影响其他页面。

## 9. 已知限制（别当成 bug）

1. 目录项（A 层）本身没有执行器，点击只会把"插件名 + 描述"填进输入框；要真跑得靠它背后对应的 runtime skill。
2. 沙箱环境无法下载 Playwright 浏览器，本次没有跑浏览器级 e2e；已用后端单测 + 类型检查 + 构建 + HTTP 联调覆盖。
3. 首页轨道最多展示 10 项，超出请走「管理插件」。
4. `blockedSkills` 统计的是 `status !== ready`；"需要你提供文件/授权"属于运行时约束，在 `HomeSkillHint` 里提示，不计入 blocked。
