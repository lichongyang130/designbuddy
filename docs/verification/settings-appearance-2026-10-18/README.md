### 真实 / 静态的边界

| 控件 | 状态 | 说明 |
| --- | --- | --- |
| 主题模式下拉 | **真实** | 跟随系统 / 浅色 / 深色，写入偏好并作用于 `html[data-theme]`，刷新后保留 |
| 明暗切换按钮（◐） | **真实** | 在浅色与深色之间切换 |
| 语言下拉 | **真实** | 与 常规 的语言下拉共用同一 store，切换立即改变 `html[lang]`（切换会关闭设置窗，这是既有行为） |
| 界面密度 | **真实** | 保留原有单选组与无障碍名称，作用于 `html[data-density]` |
| 终端主题 / 字体风格 / 内容宽度 / 文件图标 | 惰性 | `<select disabled>`，值照参考界面显示，改不动 |
| 终端链接 / 模糊与玻璃效果 | 惰性 | `role="switch"` + `disabled` + `aria-checked="false"` |
| 四张预览卡 | 静态 | 容器 `aria-disabled="true"`，内部没有任何 button/checkbox/radio |

界面上**没有**出现“未接入 / 示例数据”之类的说明（按本次要求照抄界面）；该说明写在
`SettingsSections.tsx` 的 `THEME_PREVIEWS` 注释、本文件与 README 中。

## 三、验证

```
apps/web: settings-appearance.spec.ts            4 passed
apps/web: settings-p0.spec.ts -g "appearance"    1 passed
apps/web: settings-profile-plan.spec.ts +
          settings-plan-credits.spec.ts +
          account-reference.spec.ts              10 passed / 1 failed
apps/web: settings.spec.ts                       5 passed / 4 failed
```

- 两个失败项均为改动前就存在的基线失败：`account-reference.spec.ts:13`（账号菜单动作顺序）、
  `settings.spec.ts` 的 4 条自定义模型用例。除 `settings-p0.spec.ts` 中主题交互改为下拉外，
  没有改动任何既有断言。
- 渲染截图核对（sharp 测量）：下拉 124×28、图标按钮 40×28、开关 49×20、两者间距 8px，
  均与参考界面一致；四张预览卡等宽排成一行，卡片底色分别为
  `rgb(242,244,242)` / `rgb(241,248,245)` / `rgb(247,242,216)` / `rgb(253,252,250)`；
  OCR 复核渲染图，八个标题、四条说明、四个卡片名全部正确。
- 测试环境：本机 chromium（`@sparticuz/chromium` 解压）需要设置
  `FONTCONFIG_FILE`、`LD_LIBRARY_PATH` 才能渲染中文，否则汉字会变成空白方块。

## 四、与参考界面的差异（都是面板宽度带来的）

| 项 | 参考 | 渲染 | 原因 |
| --- | --- | --- | --- |
| 区块宽度 | 819 | 642 | 设置弹窗宽度固定，按现有卡片宽度自适应 |
| 卡片宽度 | 159 | 143 | 四列等分 + 12px 间距，随容器收缩 |
| 说明文字 | 单行 | 2–3 行 | 同上，文案本身未改 |
| 语言下拉 | 124 | 185 | 选项文本沿用 `LOCALE_OPTIONS`（`简体中文 · zh-CN`），比参考更长 |
| 文件图标值 | `Qoder` | `DesignBuddy` | 保留参考行的位置与 disabled 状态，值改成产品自己的名字 |
| 额外一行 | 无 | 界面密度 | 参考界面没有这一行，但它是本产品真实生效的设置，不能因为改版而消失 |
