## 新链路不是换皮

### 网页：`web-delivery@1.0.0`

1. 按用户填写的实际标题、服务、联系信息生成 `index.html`、`styles.css`、`app.js`、`static-site.zip`。
2. `index.html` → `web.audit` → `html-audit.json`。
3. `styles.css` → `web.css-audit` → `css-audit.json`。
4. `app.js` → `code.inspect` → `javascript-report.json`。

HTML 发现任一已实现规则问题、JS 语法错误/风险提示、CSS 语法或 error 级问题，均不能记为门槛通过。CSS warning/info 保留，不能据此宣称视觉通过。缺报告、报告不可读取或被截断也不能通过。

真实串联发现旧生成器的品牌链接 `#top` 没有对应 ID；本轮修为 `body id="top"`，而不是放宽规则让它“通过”。

### 营销：`marketing-delivery@1.0.0`

1. 从所有者的实际 PNG/JPEG/WebP 素材库文件读取像素。
2. 将实际标题、副标题、行动提示传给 `image.marketing`；生成两种 PNG 和转曲 SVG、布局参数、字体许可。
3. 将 `poster-portrait.png` 的真实字节传给 `image.web-pack`，输出 `image-480w.webp` 等适配及实际尺寸/来源说明。

竖版原图1080宽时不会上采样冒充1600宽。网页图片适配只对竖版执行；方形原件仍交付，不声称两种海报都做了适配。当前没有自动视觉审美评分或裁切修复，仍须人工看图。

### 品牌：`brand-delivery@1.0.0`

1. 中文表单明确品牌名、简介、理念、口号、语气、构形和3色。
2. 由现有 `brand.system` 生成8份实质产物（另有服务生成的执行凭据）。
3. 品牌 CSS → CSS检查；规范 HTML → HTML检查。

没有将不兼容的 `brand-system.json` 直接交给 `design.tokens`。规范中的内嵌字体负载实际超过旧 HTML 文本上限；检查器现在在原始≤2MB约束下，分开计算图片/WOFF2字体base64和≤150000字结构文本，**不删除用户内容、不解码或验证二进制**，报告明确记录数量和未检查范围。字体和原图交付字节不变。

### 项目：`project-delivery@1.0.0`

1. 由真实目标、范围、需求与“怎样算完成”表格生成规格输入。
2. 仅生成技术引用 `R1/A1` 等；`product.spec` 实际校验引用与覆盖，交付 Markdown、HTML、JSON。
3. 覆盖报告有效且每项有验收条件才通过该结构门槛；未提供风险保留待补充，不把未知当作不存在。
4. 生成的 `product-spec.html` 自动做 HTML 静态检查。

## 历史、权限与失败恢复

- 原7条配方和版本不变；4条新增配方使用新ID，目录共11条。
- 旧工具收藏一次性映射到成果收藏，按组去重；原 `designbuddy.skill-favorites.v1` 不被新页面覆盖。
- 新页面收藏用独立键保存；高级工具仍使用原收藏和历史机制。
- 单项场景只向 `SkillWorkbench` 开放明确的 ID；修正了初始选择找不到时可能退到范围之外的情况。没有通过前端归组扩大服务器权限。
- 每一步仍经过真实 `SkillService` 的文件、参数、上传同意、外部单次授权、额度及所有者检查。新的品牌/网页/营销/项目链路均不要求外部模型。
- 资料提要仍须第三方单次授权。缺配置或未授权时部分完成/跳过，不生成假摘要。
- 运行中禁止同时重试；重试制作步骤时，依赖它的检查/适配会一并重新执行，不保留旧产物的检查结论；不相关的兄弟工序不被重跑。
- 门槛失败的真实报告仍可下载，运行分类为诊断，不会丢弃定位材料或标作全面完成。
- 合并工作区收起/切换/卸载会停止本地轮询，但**不取消后台记录与执行**。已用真实运行验证收起后仍完成。
- 账号身份变更会卸载工作区并中止旧读取；旧异步结果不能写入新工作区。旧历史仍按原所有者访问。
- 工作流任务标识改用 UUID，避免同一毫秒并发任务碰撞。
- 表单超长文本/行数超限改为明确拒绝，不再通过截断材料完成任务。

## 安全阻断：构建不再被误认为隔离沙箱

调查发现 `code.build` 实质是受限本机子进程，不是容器或虚拟机。仅把卡片藏在高级模式并不能保证安全，因此本轮：

1. 保留 `code.build` ID、历史、执行器源码和受控内部测试。
2. 名称明确为“本机项目构建（隔离未验收）”，登记为不可执行并说明阻断原因。
3. 服务端直接提交返回409，不因高级页面或伪造请求而放开；排队调度也阻断历史构建启动。
4. 底层 `runBuild` 仍由内部合成、可信小项目验证命令限制/真实失败，不把内部测试能力当作公开用户沙箱。

解禁条件是实际隔离执行器和安全验收，不是新增一个浏览器勾选框或临时环境变量。
