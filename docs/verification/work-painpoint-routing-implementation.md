# 痛点分类与专家路由实现记录

## 本次完成

- 首页办公任务目录增加“其他问题”，下设问题分诊、跨领域拆解、目标澄清和工具能力核对模板。
- 专家目录新增 4 个职责角色：会议纪要专家、周报总结专家、资料总结专家、问题分诊专家；内置专家总数从 12 调整为 16。原有文档、表格、汇报、协作及设计/开发专家继续覆盖对应分类。
- 本地规则路由优先识别会议纪要、周报/总结、资料归纳和不确定问题，避免被广义文档规则抢先匹配。
- 在线匹配结果现在允许一位主责专家和 0–2 位可选协作专家；API 对协作角色做候选目录、去重、不得与主责重复等校验。专家面板展示可选协作，发送时把协作角色作为补充工作规范附加，不改变单一主责。
- 专家详情页任务样例复用现有首页模板；目录数量改为动态显示，不再写死“12位”。
- 新角色的职责说明明确区分指导档案与执行工具；没有因新增专家而增加任何真实技能绑定。

## 仍未完成 / 能力边界

- P1 的首页首屏独立痛点卡片、统一任务计划与证据/执行状态界面尚未全部落地；目前“其他问题”在首页分类任务目录中可选，专家职责可在专家页查看。
- 中文、多语种、长会议 ASR 仍未接入。会议纪要专家只处理实际提供、可访问的文字记录，不会从音频直接生成转写或纪要。
- 周报/资料总结没有新增自动采集项目系统、批量摘要或外发能力；需使用真实可用模型、材料与现有工具，并由用户复核。
- 因此本次是目录、路由与职责层的阶段性实现，不代表方案全部完成或新增专家已获得执行权限。
