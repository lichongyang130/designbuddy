# Word Pro 首批 W0＋W1＋W2：实施与验收记录

日期：2026-10-19。范围来自[已批准实施方案](plans/word-output-quality-v1.md)。本文描述受限的原生生成、同源渲染和有限排版修复，不代表商业视觉、事实、法律或目标Office认证。

## 用户可用结果

- 模版 → 文档 → **Word专业排版 · 真实分页与有限修复**，路由 `/inspiration/word-pro`。
- 两个实际案例：`apps/web/public/word-examples/word-pro/{business-report,project-plan}/`。
- 下载原生 `document.docx`、由同一DOCX渲染的 `document.pdf`、全页联系表 `word-pages.jpg`、`word-quality-report.json`、完整 `word-delivery.zip`。
- 可以逐页查看实际JPEG、用本地PDF.js查看最终PDF和初始PDF、查看每轮问题/动作/哈希。
- 原创方法教学案例，不是用户业务事实或外部模型生成质量验收。商业报告输入故意含超宽表格、未启用重复表头及标题保护，真实触发三项白名单动作；项目方案使用正常参数与独立必需章节。
- 最终商业报告与项目方案均为4页；商业报告实际修复1轮、3项动作，项目方案无需修复，两者自动检查均0项关键问题，仍需人工复核。准确哈希和修复记录以各自 `manifest.json`、根目录 `index.json` 和质量报告为准。

### 用自己的内容

案例页下方独立工作台，或文档专家选择 `document.create`：

1. 选择商业报告或项目方案。
2. 填写标题、来源/定位和相应章节的实际内容；缺少事实明确写待确认，不自动补造。
3. 可粘贴制表符分隔的原生表格，填写表题、字段/单位/范围口径、计算说明。数值保留字符串，不执行公式。
4. 点击“将Word文稿准备为输入”；此时仍在浏览器本地，未上传。
5. 另行同意上传/后台保存并执行，等待真实事件流；下载成果并人工复核。

高级模式可载入完整WordDocument V1 JSON，保留多来源、表格及已授权PNG/JPEG/WebP。普通表单不要求用户写JSON，但本批没有旧Word直接导入、AI全文生成或图片编辑器。两种类型的正文草稿分别保留在当前组件内存，切换类型不互相覆盖；离开页面前须保存，未宣称云端编辑工作区。

任何准备内容修改都会撤销已准备文件和后台执行同意。原始导入JSON与表单模式分开，不将导入文档的内容悄悄替换为另一个类型的章节。

## 两类文档不是一张皮肤

商业报告必需且依序包含：执行摘要、分析与依据、建议与行动。项目方案必需且依序包含：目标与背景、范围与非范围、交付物与建议关卡、风险与应对、验收条件。额外子标题受1–3级层级约束，章节不能只有连续标题。

商业报告采用墨绿、项目方案采用商务蓝；共享的是纸张和基础可读样式，不是PPT固定画布布局。短文档的章节导航与正文自然衔接，不为三个目录条目强制占满一个空页面。表格题注与表头受保护，图片、题注、说明、许可与来源形成连续保护链，避免图片留在上一页而来源掉到下一页。

## 事实与内容保全

- 原始请求哈希、节点文本/单元格、逐节点来源绑定、来源全文、图片原始/规范化哈希写入交付记录。
- DOCX生成后重开Office包，并在正文书签边界内核对节点文字；不拿附录或章节导航的重复文字冒充正文存在。
- PDF文字匹配只去除空白/零宽分隔，不改数字、单位或做Unicode兼容折叠；附录文字不计入正文覆盖。全局出现不证明该句在正确章节，也不证明语义、视觉位置或事实正确。
- 来源全文放在 `content-manifest.json`；DOCX附录显示来源定位（原文哈希在交付清单），不重复排印所有原文。不能把这解释为静默丢失来源。
- 内容哈希覆盖标题、正文、表格值、引用/来源与图片声明，排除明确的版式字段；每次修复重新比较，变化即中止。
- 不联网研究、不调用正文或图像模型、不执行材料中的指令，不推断预算、责任人、进度或审批结果。

## 有限修复闭环

初始生成/渲染/检查后，最多两轮修复（共三次完整渲染），每轮检查全篇。动作只有：

1. 恢复标题与后文保持 `keepNext`。
2. 在最小12mm列宽约束下重分170mm版心内的表格列宽。
3. 恢复跨页重复表头。
4. 将完整图片等比例缩小到170×210mm安全框，不裁切或拉伸。

每轮记录DOCX/PDF哈希、内容哈希、实际页数、问题、动作及后续新增/消失的问题。`iterations/<round>/` 保存每轮真实DOCX/PDF/渲染记录。发现新的关键问题即回退上一版本并停止；当前版本仍有问题时保留诊断，不宣布通过。

未可靠定位的空白页、页尾标题或文字边界只报告候选，不自动删除空页/分节、移动正文、拆表或缩小全文。拆表、横向分节、实质文字修改均非本批动作。

正常结果为 `needs-human-review`，有关键问题为 `blocked`；都是草稿，`commercialApproval=false`。评分权重保留用户建议，未校准综合分为null，不用高分抵消硬问题。

## 渲染、目录与编辑边界

- 最终PDF、页图以最终DOCX字节为输入；绑定最终哈希，不能混用修复前后产物。
- 真实LibreOffice Kit当前Linux可为WASM后端，不是Microsoft Word/WPS结果；准确后端在报告中。
- 章节导航采用原生内部超链接，无目录页码，不宣称TOC缓存已经刷新。
- 页脚包含原生PAGE/NUMPAGES。实际页数来自PDF，目标客户端字段刷新/页眉页脚仍须人工检查。
- DOCX文字、标题、表格、独立图片、页眉页脚可编辑。示意流程图是图片对象，图内不是逐节点编辑；不宣称已有原生Word图表。
- DOCX不内嵌字体，接收端需安装Noto Sans SC；OFL许可在交付包。部署字体按现有来源和哈希验证，不把PPT字号规则搬过来。
- 缺字会在生成前失败。渲染器报告缺失字体时为关键问题；“未报缺字体”不等于目标Office字体一致。

## 已设置的资源与安全约束

- 单JSON≤2MB；3–250节点；1–30来源，每份来源正文≤20000字，来源正文和内容清单合计≤50000字。
- 2–8列表，1–100数据行，合计≤2000格；每个单元格≤500字。最多4张已授权位图，每张原始≤1MB，整个JSON仍≤2MB；规范化另受已有图片解码/像素/EXIF规则约束。
- 最多20物理页；本地转换/页图调用各有60秒期限；超过170秒不启动下一轮，整任务300秒Worker硬截止。
- 交付合计沿用10MB；所有者配额、运行数和并发约束沿用服务。多个上限不保证任意极限组合都成功；超限明确失败，不截断内容。
- 受控临时文件、输出路径/长度校验、Office包安全重开；无外链抓取、宏、脚本、任意路径或可执行代码入口。
- 成果通过原有事务持久化，失败不产生虚构下载。当前Word没有恢复检查点/自动续传；不展示“从断点继续”按钮。
