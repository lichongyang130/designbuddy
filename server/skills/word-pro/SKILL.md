# Word Pro 1.0 — 首批工作规范

本文件是人工/Agent工作规范，不是动态加载器。实际注册点：`shared/skillRuntime.ts` 的 `document.create`、`runtime-catalog.ts`、`executors.ts`、`service.ts`；执行入口 `pipeline.ts`。

## 何时使用

用户要新建商业报告或项目方案，并提供实际正文/数据与来源时使用。当前可通过WordComposer填写，或提交严格WordDocument V1 JSON。不是纯主题AI写作、外网调研或已有Word无损编辑；不能把聊天回答当成已执行任务。

## 内容与权限

- 由章节角色选择两种结构，不按标题猜测审批、日期、负责人或实际业绩。
- 来源、节点与数据保留字符串原值；来源引用存在不等于事实已核验。
- 表格需要字段含义、数据范围、单位与计算说明。无计算须明确写明。
- 仅接收确认有权使用的PNG/JPEG/WebP；本地规范化。证据图完整显示，装饰图不得支持事实主张。
- 不调用模型、不联网抓图、不外发像素。上传/后台持久化需通用工作台的单次确认，修改准备输入撤销确认。
- 来源全文在交付包content-manifest.json保留，DOCX附录展示来源定位，原文哈希在交付清单，不重复排印整份原文。

## Word排版与检查

使用A4、固定可读字号、原生标题/正文/表格/图像、页眉页脚和PAGE/NUMPAGES字段。章节导航是无页码内部链接，不宣称已更新自动目录。DOCX不内嵌字体；部署和目标端字体分别验证。

生成后必须重开Office包并核对正文清单。以该轮同一DOCX渲染PDF和全部页图，记录文件哈希、实际页数、引擎与缺字体信号。不以独立生成PDF或HTML模拟分页代替真实预览。

PDF文字匹配不等于语义或像素检查；附录原文不能用来替代正文覆盖。重复文字会妨碍精确定位。空白候选、边界候选、页尾标题候选无法可靠判断时不自动修改。

## 有限修复

仅允许恢复标题keep-next、在12mm最小列宽下重分170mm版心、恢复重复表头、将完整图片等比缩小到170×210mm框内。不是OCR或图像重绘。

禁止删文字/数据、隐藏表格行列、改变口径、改写主张、裁证据图或将全文缩字。拆表、横向分节、实质正文变化需用户确认，不属于本批动作。

最多两轮修复/三次完整渲染；每轮全篇检查、比较内容哈希、保留前后DOCX/PDF及动作记录。新关键问题触发回退并停止。到达时间/页数/体积限制明确失败，不宣布完成。当前没有可恢复Word检查点，失败后重试属于新任务，不伪造继续进度。

## 交付

Word、同源PDF、全页联系表、内容/来源清单、质量报告、含逐页图和历次DOCX/PDF的ZIP；通过现有任务/下载服务持久保存并按所有者隔离。

有关键问题：`blocked`诊断草稿；无关键问题：`needs-human-review`。两者均`commercialApproval=false`，综合评分未校准为null。自动结构通过不代表视觉、事实、法律、版权或Word/WPS兼容性批准。需要人工逐页核验并记录目标客户端与字体环境。
